The collapsed tool one-liner

Two independent changes, judged separately because they can ship separately. §2–§4 — what the line says: a shell row lists the commands the agent ran, not their arguments. §5–§8 — how the line looks: a tool row is currently the loudest and tallest row in the transcript; it should be as quiet and as tight as the thinking row right above it.

The expanded body of the same row is a separate board: mockups/tool-expanded-body.html.

Reading this board: every grey is a real theme.dart token, every glyph is drawn to the Phosphor-Light metrics the app uses (stroke 1.5 on a 24 box), and every proposed label in §2/§3 is computed live by the JavaScript at the bottom of this file from the real command text — it is the reference implementation for the Dart port, not a hand-typed illustration.

⚠ One conflict in the brief — now settled. The example line reads Ran grep, gh pr, … (past tense) but the typography note asks for present tense (“Run, Edit, Write”). Confirmed with the author: present tense wins, which is what this board renders (§8 has the full verb table).

2What “the commands it runs” means, precisely

A shell command is not one command. It is a pipeline of segments, wrappers, substitutions and loop bodies. Seven rules, in order — each one exists because a real command in the corpus below breaks without it.

  1. Split into segments at top level: |, &&, ||, ;, & and newlines — quote-aware, so -m "a && b" stays whole. Pipelines do split now (today they don't): grep … | head is two tools, and the brief's example line lists both. grep -rn x src | head -20 → grep, head
  2. Recurse into command substitutions $( … ) and backticks, appended after their host segment — that is where lsof usually hides. kill $(lsof -t -i:9787) → kill, lsof A redirection is neither a separator nor a command: pnpm typecheck > log 2>&1 → pnpm typecheck (not pnpm typecheck, 1)
  3. Drop prologue & shell keywords. cd, export, source, set -e, bare FOO=bar and the for/while/if/case loop headers carry nothing. The loop body is a later segment, so it still contributes. The old +env marker is dropped — in a list of names it is pure noise. for f in *.dart; do wc -l "$f"; done | sort → wc, sort
  4. Unwrap wrappers, then take the basename. sudo env time nice nohup xargs timeout stdbuf are skipped, as are leading flags; ~/flutter/bin/flutter → flutter, ./scripts/deploy.sh → deploy.sh. Versioned interpreters normalise (python3, python3.12 → python; pip3 → pip) — the brief's example says python. time ~/flutter/bin/flutter test --no-pub → flutter test
  5. Keep the subcommand for multiplexers only (§3 table). For everything else the second token is discarded — grep rg sed awk head lsof python curl jq ssh rsync tell you what happened by their name alone. A heredoc body is never scanned. gh pr view 154 --json title → gh pr  ·  sed -i '' 's/a/b/' x.ts → sed
  6. Skip filler subcommands run, exec, dlx, -- and take the next word: the script name is the information, not the runner's plumbing. pnpm run build → pnpm build  ·  pnpm exec tsx test/e2e-server.ts → pnpm tsx
  7. De-duplicate, keep first-seen order, cap the list. Eight names, then +N — a safety valve for a 30-segment script, not a width control (the row already ellipsises). Repeats collapse (a three-grep sweep is one grep); the ×3 multiplier is available as a toggle below but off by default. grep a && grep b && grep c && wc -l → grep, wc

3Which binaries keep their second word

This is data, not logic — one const Set plus one const Map. The test for membership: does the bare name leave you asking “doing what?” git alone is meaningless; lsof alone is complete.

Subcommand kept

—

Nouns (optional depth-3)

decide

The case for depth-3: gh pr hides the difference between reading a PR and creating one — the widest possible gap in consequence. gh pr view costs 5 characters. Toggle it in §2 and judge the width.

Name only

no subcommand

Unknown binaries default to name-only. A tool the table has never seen (dbvr, shoot-ports.sh, some repo script) renders as its bare name. That fails quietly and is never wrong, whereas defaulting to “keep the second word” would print rm -rf as rm -rf… and curl https, ssh le@host, jq .items as noise. Add names to the set when a real transcript proves the need.

4What this throws away, and the two things that catch it

Be honest: Run grep tells you less than grep "copyWith" app/lib/store. The argument is gone from the collapsed row. Three answers, in order of cost.

A — hover shows the command

recommended

Cost: one Tooltip around the existing Text carrying compactCommand() — the whole command with only the cd/export prologue stripped, segments joined with ›, which is what the rows below show — at a 500 ms dwell (kTooltipDwell, already app-wide). Pointer-only — which is fine, because on touch the whole row is already a tap-to-expand target. (Third row shown pinned open; the others react to a real hover.)

B — expand is unchanged

free

Cost: zero. _BashRenderer.body already shows the full command in a syntax-highlighted block plus the output. The collapsed row was never the place to read a command.

C — keep args when there is one command

rejected

Why not: two layouts for one row. The single-command case is the majority, so the “calm list of names” you asked for would be the rare rendering, and the row would still be a monospace path dump most of the time. Consistency is the whole point.

The real argument for it: read/edit/write rows carry paths, and paths are what monospace is for. Against: two families per line, and the mix reads busier than either pure option at this size. Your call.

rejected

Why not: italic is doing semantic work in this transcript — it marks the agent's inner voice (thinking, the working indicator's shimmer word). Tool rows are facts, not musings. Sharing the family and size is consistency; sharing the slant erases a distinction.

6Compactness: a tool row is 44% taller than a thinking row, for no reason

Both rows sit inside transcriptRow (kChatRowGap/2 = 5 above and below). ThinkingLine adds nothing. ToolCallCard wraps its row in an InkWell with vertical: kSpace6 — 12 px of padding that exists only because the row is tappable.

On a 900 px-tall transcript with 14 tool rows that is 112 px — three more rows of history per screen. The gap also shrinks sideways: glyph→text kSpace8 → kSpace6 and the trailing cluster's two kSpace8 gaps → kSpace6.

⚠ The one thing to weigh before taking all 8 px: touch targets. At 39 px the row is already under Apple's 44 pt (kTouchRow) and Material's 48; at 31 px it is further under. It is full-width, so the miss rate is low, and nothing destructive is one tap away (expanding is free and reversible). Options: (a) take it everywhere — recommended, the transcript is a reading surface; (b) kSpace2 on pointer, kSpace6 on touch — a real conditional in a widget that has none today; (c) kSpace4 everywhere for a 35 px compromise.

7Monochrome glyphs: the risk tint is already meaningless

Not a taste argument — a signal-to-noise measurement from the two servers that emit risk.

Evidence.
  • server/src/pi-sessions.ts:259 — classifyRisk returns risky for edit, write and bash; everything else is safe. destructive is never emitted at all.
  • server/src/adapters/acp-map.ts:540 — risky for edit, move, execute; destructive only for the delete kind.
  • So on a normal turn — read, grep, edit, edit, bash, bash, bash — the amber glyph fires on every row that is not a read. A warning that is always on is decoration, and the app spends its only two extra hues (kToolRiskyColor, kToolDestructiveColor) on it.

Monochrome, exceptions only

Colour is spent only where it is exceptional: a failed call keeps colorScheme.error, and the running pulse keeps primary (at most one or two rows, and it is the only “alive” signal). The resolved tick drops to onSurfaceVariant @ .55 — same as the glyph.

Destructive still tints

keep in reserve

If ToolRisk.destructive ever starts arriving (ACP delete), a single red glyph on an otherwise grey column is enormously visible — which is exactly the point of keeping it unspent. Recommend: keep the destructive branch, delete the risky one.

Decisions.
  • Tense — SETTLED: present tense (Run, Edit, Write), confirmed by the author. §8 is the verb table to implement.
  • Depth — shipped at depth 2 (gh pr), the brief's sketch. gh pr view is a one-line change in _multiplexers' companion map if you want it.
  • Payload family — shipped all-sans (§5B). Judge it on the real captures before revisiting §5C.
  • Touch target — still open (§6): 31 px everywhere as shipped, or kSpace6 on touch only.

The status language — statuses, in-app notifications, attention

Every way makit reports state, audited for coherence across iOS and macOS · feat/status

What this covers. makit has five independent status languages — session status (6 states × 3 renderings), connection state, PR state, SPEC-48 severity, and OS notifications. Each was designed well on its own. Nobody has drawn them together, and DESIGN.md’s own rule is that a state must “read identically everywhere”. This page draws them together, finds three places where they contradict, and designs the one signal that is missing entirely.
The headline gap. You are in session A on your phone. Session B moves to awaiting-approval. The agent is now blocked, waiting on you. makit shows you nothing — no toast (SPEC-48 D7 posts session lifecycle silently), no OS notification (those only fire when backgrounded), no badge. The only signal is a dot changing colour on a screen you are not looking at. §4 fixes this.

1 · The inventory — one state, four vocabularies

SessionStatus has six values. Each is rendered by SessionStatusDot (colour + tooltip), SessionStatusChip (a terse pill), notificationFor (prose on the lock screen) and — since SPEC-48 — an Activity severity. Four names for the same fact.

Two names are wrong even before the audit. The chip for awaitingInput is “you” — a pronoun as a state name, which parses as a label for whose turn it is only if you already know the convention. And awaitingApproval is “approve”, an imperative verb: it reads like a button you can press, in a pill that does nothing. Proposal: needs you and approve? — or keep the width and use you / ok?. The point is that a state label should be a state, and a verb should be a control.

idle and exited are indistinguishable — same hue, same no-pulse, same notification prose — yet one means “ready for your next message” and the other means “this process is gone”. Only the chip label separates them, and the chip is not shown on the sidebar tile.

2 · Contradiction #1 — the caution tier disappears in Activity

kStatusCaution #E07B39 exists precisely because “awaiting approval” is a stronger act-now than “awaiting input” — DESIGN.md says so, and five call sites honour it. status_tone.dart has zero mentions of caution, so SPEC-48 flattens approval into warning amber.

One hue per meaning, everywhere — the rule prStateStyle and SessionStatusDot already exist to enforce.

  • Small change, real coherence. One value in StatusSeverity, one arm in statusColor / statusGlyph, one arm in notification_observer’s mapping, one dwell entry.
  • It also fixes severity ordering. Approval-blocked is strictly more urgent than input-wanted (an agent is stopped), so caution must sort above warning for worstUnread and the filter threshold.
  • A sixth severity is a wider enum, and theme_contrast_test.dart must cover the new fill. statusCautionText already exists for the light-mode label, so the contrast work is done.
  • Alternative, cheaper: leave the enum at five and only re-map the hue for approval events. Rejected — a severity that renders in a colour outside its own tone table is exactly the drift status_tone.dart was written to prevent.

Glyph, too. A raised hand for “approval” separates it from the triangle used for “warning”. Severity is currently colour-and-glyph, and the glyph is doing no work here because both states share one.

3 · Contradiction #2 — the pulse means two opposite things

SessionStatusDot pulses for running and for both awaiting states. But “running” means relax, I’m working and “awaiting” means stop, act now. One animation, opposite instructions — and the pulsing green is the one you’ll see for hours.

Give motion one job: urgency

RECOMMENDED

today — everything active pulses the same way

running fade 0.3 → 1.0, 1 clock
awaitingInput identical motion
awaitingApproval identical motion

proposed — motion only where you must act

running steady, slightly dimmed — “busy”
awaitingInput breathing halo — “your turn”
awaitingApproval same halo, caution hue — “blocked on you”
error static — it already happened
  • Motion becomes meaningful. If only “act now” moves, a moving dot is worth looking at. Today motion means “not finished”, which is most of the time.
  • Cheaper on the phone. running is the common state and it currently animates every tile on the sessions list; a steady dot leaves nothing ticking (the exact reason SessionStatusDot already avoids Opacity layers).
  • Still not colour-only. The halo is a shape change, so the “act now” tier survives colour-blindness and greyscale — the tooltip/semantics label stays as it is.
  • Losing the green pulse costs a “something is happening” cue. But that cue is already carried better elsewhere: the shimmering busy word in the transcript, and the composer’s cancel button.

4 · The missing signal — attention, in-app, across sessions

SPEC-48 D7 says session lifecycle posts silently because “a session you are looking at already shows its own status dot, and the OS notification is what handles you-weren’t-looking”. Both clauses are true. Neither covers the case in between: app open, looking at a different session. On a phone that is most of the time, because a phone shows exactly one session.

Why a toast cannot fix this

PrimitiveAnswersLifetimeRight for “B needs approval”?
Toastwhat just happened3–8 s dwell No — the need persists after the toast dies; a transient view of a durable state is a missed call
Activity rowwhat happened, historicallyforever (in memory) No — you must already be looking for it
Status dotwhat is true, per sessionas long as it’s true No — correct lifetime, but only visible on a screen you are not on
OS notificationsomething needs you, awayuntil dismissed No — suppressed in the foreground, correctly
Attention bar (new) which other session needs you, now state-bound — lives exactly as long as the state Yes

The design rule this exposes. makit’s status layer conflates events (a thing happened; past tense; a record) with states (a thing is true; present tense; resolves itself). SPEC-48 built an excellent event system and then routed states through it, which is why the states came out silent. Attention is the state-shaped primitive: it is never dismissed by the user, it disappears when the session stops needing you.

Tapping the aggregate opens a “Needs you” list — sorted caution before warning, each row deep-linking to the session. Two blocked agents is a queue, not two banners.

  • It reuses the primitives already on screen. Caution rail, halo dot, session name, agent — nothing new is invented, so nothing can drift.
  • Correct lifetime by construction. Derive it from sessionsProvider — the set of sessions in an awaiting state, minus the one on screen. No state to own, no queue, no timers, nothing to leak. Answer the approval and the bar is gone on the next frame.
  • It makes SPEC-48’s D7 silence correct. D7’s reasoning was right — a toast per finished turn is noise. The mistake was having only two volumes: toast, or nothing. This is the third: persistent, quiet, and not in the way.
  • It costs 32 pt of the transcript — and only when an agent is blocked on you, which is the one moment you would trade 32 pt for. It must sit below the glass bar (never over it) and above the transcript, so the composer is untouched.
  • Third thing anchored to the top edge, after the glass bar and the toast. Ordering must be fixed and documented: glass bar → attention → toast stack. A toast is transient and may overlap; attention may not.

What it is not. Not the bell (that is history), not a toast (that is an event), not the connection chip (that is transport). One new widget, SessionAttentionBar, driven entirely by derived state.

  • One rule, two shells. “Show attention for awaiting sessions that are not currently visible.” On macOS with the sidebar open that set is usually empty, so the bar never appears and the tile rail carries it — the desktop stays quiet for the same reason the phone gets a bar. Same predicate, different visible set.
  • The macOS extras are free. A Dock badge count and a Window ▸ Needs You menu item both read the same derived set — and on macOS a Dock badge is the platform-native answer to “not looking at this app at all”.
  • “Visible” needs a real definition in a split view: a pane counts as visible only if it is on screen and its session is the one the pane shows. Cheap to get wrong, so it belongs in one provider with tests, not inline in two widgets.

No session name, no content — APNs never carries it (docs/PUSH.md). Tap → reconnect over the tailnet → the real request.

Same event, same words, one volume quieter — and it persists, because the state does. This is the whole proposal.

One prose source. “needs approval” here and “Agent needs your approval.” on the lock screen should come from notification_policy.dart, not a second string table — otherwise the two drift the way the chip labels already have.

6 · System status — connection, transport, demo

ConnectionChip is the one place makit reports its own health. Its best decision is that connected renders nothing — zero chrome on the happy path. Worth keeping, with one gap named.

The degradation ladder

AS BUILT

connection_chip.dart — plus the one state it cannot express

connected — nothing at all —
connecting Connecting
reconnecting Reconnecting tap to retry
closed / idle Offline tap to retry
useFake Demo always shown — seeded data
  • Hiding the happy path is right and should be the model for every status in the app: chrome proportional to trouble. The attention bar in §4 follows the same rule.
  • Offline invalidates every other status on screen and doesn’t say so. While the socket is down, every session dot is a stale cache — “running” may have finished minutes ago. Proposal: when closed, desaturate session dots and add one line to the chip’s tooltip (“statuses last updated 4m ago”). Cheap, and it stops the UI asserting things it cannot know.
  • Offline is a state, so it belongs in Activity too — “Disconnected” / “Reconnected” with the elapsed gap is exactly the durable record SPEC-48 exists for, and today the chip is the only witness.
  • Demo mode being always-visible is correct and is the only status that earns permanent chrome, because everything else on screen is fake.

7 · What I would change, in order

Ordered by coherence gained per line changed

1–3 are small and fix contradictions; 4 is the feature

#ChangeWhereWhy
1 Add StatusSeverity.caution status/status_event.dart, status/status_tone.dart, notifications/notification_observer.dart One state currently renders in two hues on one screen. Sorts above warning; glyph = raised hand; dwell 8 s. statusCautionText already exists, so light-mode contrast is solved.
2 Motion means urgency only ui/widgets/session_status_dot.dart running stops pulsing; awaiting states get a breathing halo (a shape change, so it survives greyscale). Also removes an animation from every tile in the common state.
3 Fix two chip labels ui/home/repo_chips.dart you → needs you, approve → approve?. A state label must not be an imperative verb; and idle vs exited deserve distinct words wherever both can appear.
4 SessionAttentionBar + attentionProvider new: status/session_attention.dart; mounted in the phone shell and the desktop pane column The one signal that does not exist: app open, blocked agent in another session. Pure derived state (awaiting sessions − visible sessions), so nothing is owned and it clears itself. Prose from notification_policy.dart, not a second string table.
5 Offline invalidates statuses ui/widgets/connection_chip.dart + dot rendering While the socket is down, every dot is a stale cache. Desaturate them and say when they were last true, rather than asserting what cannot be known.
6 Connection transitions post to Activity store/connection.dart → StatusCenter “Disconnected 12:04 → reconnected 12:09” is the durable record SPEC-48 is for; today the chip is the only witness and it forgets instantly.
7 Dock badge + Window ▸ Needs You macOS shell — follow-up Same derived set as #4, and the platform-native answer to “not looking at makit at all”.

What I am not proposing. No new OS notification triggers (SPEC-07/08 decide what buzzes; this only changes what the app shows while you hold it). No persistence (D9 stands). No per-source mute settings. And no toast for session state — that was the right call, it just needed a third volume rather than a louder one.

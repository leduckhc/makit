Context usage — ring + details panel — SPEC-context-usage

A circular gauge in the composer footer; tap/click opens the full detail. Real numbers throughout, from the verified runs: codex 19440/258400, pi 29408/1000000 · $0.18.

✓ Why this is the right shape. The ring is a 32 pt tap target with no label — 5× cheaper than the full pill's 166 pt — and the numbers get a whole panel instead of 12 pt of ellipsized text. It also matches an existing makit pattern exactly: GithubBudgetButton is a coloured mark that opens a popover, so this is a second instance of a convention rather than new chrome.
⚠ It does not fix the crowded mobile footer, and nothing in-row can. Measured on this page: pills get 267 pt on a 375 pt phone, and a 3-config-pill pi session already needs 279 pt — over budget before usage exists. Adding the ring leaves 235 pt, so those three pills clip (see the first frame below: Sonn…, San…, Appr…). A 2-pill codex session has room and renders cleanly. Trimming that pill row is a separate problem — flagged, not touched.

Re-measured in the running app (2026-08-06), and it is worse than this page implies. There is no RenderFlex overflow — the Flexible wrappers prevent it — but with a longer model name the row wants 500 pt of natural width (model 225.5 + thinking 88 + mode 150.5 + ring 36) against the same 267 pt, so each label is squeezed to 21.8 pt: one glyph plus an ellipsis (C…, h…, A…). Scrolling the row would push the ring ~250 pt off-screen, so the fix is the SPEC-model-picker-menu-per-model-config shape — fold the legacy model/thinking/mode trio into one pill that opens a sheet, as ModelConfigFooter already does for agents that send configOptions. Still out of scope here.
✎ Amended after the first build (2026-08-06). Two things on this page were wrong about pi, and both are fixed — the frames below now show the shipped behaviour.
  • pi does have a breakdown. The old pi frame showed cost only, captioned "pi reports no token breakdown". It reported none because the extension sent none — not because pi has none. Totals are now summed from pi's own session entries, so the pi panel is as detailed as codex's.
  • Cost was per-message, not per-session. The panel showed $0.20 on a session pi's own /sessions priced at $22.16 — it was forwarding the last assistant message's cost into a field documented as cumulative. The pi frame below now carries that real session: 33.7M billed · 288k in context · $22.16.
  • Resumed sessions count. Totals are re-derived from the session entries every turn rather than accumulated in memory, so a resumed session inherits its earlier spend (and a compaction's own tokens, which never arrive as an assistant message).
  • The install changed. The extension moved to its own repo, github.com/leduckhc/makit-pi-usage, installed as a pi package. The symlink this page used to reference dangled the moment its worktree was pruned, and pi then silently loaded nothing.

pi, post-compaction
— nothing rendered —

pi keeps reporting the window but nulls the count until the next reply. A 0% ring would misread as "context emptied".

There is no "unmeasured" ring. Every unknown state renders nothing at all. An empty ring cannot be told apart from a real 3% reading at 18 px, and the two mean opposite things — so the ambiguous rendering is simply not offered.

The one honest weakness: at 3% the arc is a short tick — you cannot read "3%" off the ring itself. That is the accepted cost of a 32 pt control; the ring answers "is my context filling up?" at a glance, and the panel answers "by how much exactly?" on demand. That trade is the entire point of the click.

⚠ Still out of reach: what the context is MADE OF. The panel shows input / cached / output / reasoning, which codex and pi both report. It cannot break context down into system prompt vs tool definitions vs skills vs MCP vs messages — no agent protocol reports that, and estimating it would produce numbers that disagree with the provider's. The one exact figure available is a fresh session's first-turn input (system prompt + tool defs + AGENTS.md, measured at 19,487 tokens on codex); say the word and it can join this panel as "baseline".

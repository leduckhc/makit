Chat Input UX/UI Review

Specialist lens: composer field, slash palette, send/cancel affordances, accessibility

✅ Strengths

Adaptive State Layering

Compact/expanded toggle matches mobile/desktop needs. Draft persistence prevents data loss on navigation.

Keyboard Affordances

Configurable send/newline chords. Default Ctrl/Cmd+Enter + native Return is predictable.

Visual Hierarchy

Clear send button state machine (text→active, running→stop, empty→disabled). Slash palette badges help disambiguate sources.

MEDIUM

1. Slash Palette Scrolling Context

Problem: Fixed height (280px) scrolls independently. On narrow windows it may obscure the input field, create nested scroll zones, and offer no visual indicator of how many commands match.
Recommendation:
  • Cap palette height to 50% of available composer space (not hardcoded 280px)
  • Show match count badge ("43 skills") in palette header
  • Add keyboard arrow-key cycling through matches (↑/↓ to navigate, Enter to pick)
MEDIUM

2. Hint Text Clarity

Problem: "Message …" is too generic for an agent-first IDE. User may not know: can they paste code? Can they attach files? What slash commands exist?
Recommendation:
  • Change hint to: "Message, /slash, or paste code …"
  • Or show transient micro-tooltip on first focus: "Tip: type '/' to see commands"
MEDIUM

3. Send Button Affordance in Compact Mode

Problem: State change (disabled gray → enabled blue) is subtle. No visual indication it's clickable. Tooltip only on hover.
Recommendation:
  • Add visual pulse/glow when text is entered (feedback that send is now active)
  • Or make disabled state more obviously "off": dotted border, 40% opacity
  • Ensure keyboard focus visible when tabbing (golden ring)
MEDIUM

4. Multiline Field UX Friction

Problem: Auto-growing 3→10 line field works but: scrollbar is hidden, user typing at bottom may not see earlier lines, on narrow displays (split panes) 10-line growth eats vertical space fast.
Recommendation:
  • Show subtle scrollbar hint (always visible, fades if not scrolling)
  • Cap max-lines to 6 on narrow viewports (<600px) via MediaQuery
  • Add keyboard indicator in hint: "Shift+Return for newline"
HIGH

5. Cancel Button Placement (UX Debt)

Problem: Cancel button only shows when running == true AND onCancel != null AND _hasText == false. This means:
  • User can't see cancel affordance while typing a follow-up message during a long turn
  • If field is non-empty, send button obscures stop button — user must clear field first to cancel
Recommendation: Show cancel button always when running, prioritize it over send:
if (running && onCancel != null) → stop (red) else if (_hasText) → send (blue arrow) else → disabled send (gray)
This way user can cancel mid-turn without clearing draft.
MEDIUM

6. Attachment Button State (UX Debt)

Problem: Plus button is disabled (grayed, onPressed: null) with comment "Disabled until M6 (@-mention picker)". This looks broken, not planned. Takes up real estate for a placeholder. No affordance explaining why it's disabled.
Recommendation:
  • Hide the button entirely until feature is ready
  • Or replace with info icon + tooltip: "Attachments coming in v2"
  • Better: Replace with a working quick-command button (e.g., "Last 5 commands") if attachment is months away
LOW

7. Composer Padding/Inset Consistency

Problem: Nested padding across three layers creates inconsistency. Total ~12–14px left/right is asymmetric when scaled, 20px top/bottom feels loose.
Recommendation: Consolidate into a single design token (e.g., composerPadding = 12) to centralize future tweaks.
MEDIUM

8. Desktop Focus Management After Send

Problem: When user sends a message, composer unfocuses (_focus.unfocus()), returning focus to transcript. On desktop, this means:
  • User must click back in the composer to type the next message (extra click)
  • Tab cycle breaks (focus jumps to transcript, then back to composer)
Recommendation:
  • Desktop only: Re-focus the field after send (on mobile, unfocus is correct)
  • Check if externally-owned focusNode interferes; if so, add callback: onSendComplete: () { _focus.requestFocus() }

📋 Summary: Prioritized Fixes

🔴 High Priority (UX Debt)
  • Cancel button visibility: Show when running, even if field has text
🟠 Medium Priority (Friction)
  • Slash palette keyboard nav (↑/↓) + match count badge
  • Hint text: "Message, /slash, or paste code …"
  • Send button affordance: pulse on text entry or opacity change on disabled
  • Multiline field: show scroll indicator, cap lines on narrow viewports
  • Attachment button: hide until ready or replace with working feature
  • Desktop focus: re-focus field after send
🔵 Low Priority (Polish)
  • Padding token consolidation (design system debt)

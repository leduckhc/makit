What this branch has not fixed. The new top card is better placed and the record is durable, but: copy is a 13 px icon inside a 24 px button — the smallest target on the card is the action you need most; the dwell timer runs regardless of whether you are reading it (grep -c MouseRegion status_toast.dart → 0); and reviewing still means navigating to another surface. Four rules below, in the order I would ship them.

Rule 1 · If you are reading it, it does not leave

The cheapest fix in the whole page, and it removes most of the panic. A dwell timer should measure inattention, not elapsed time. Point at it (macOS) or touch it (iOS) and the clock stops and the detail unfolds; leave and it resumes with the full dwell, not the remainder.

  • Fixes the desktop race where the notice dies while the mouse travels toward it. On iOS, touch-and-hold does the same job.
  • Resume with the full dwell. After you look away it is news again — the same reasoning the toast layer already uses for a coalesced repeat.
  • A frozen card can be forgotten under a stationary pointer. Cap the freeze at 30 s, then fade — the record still holds it, so nothing is lost.
  • Touch-and-hold on iOS competes with swipe-to-dismiss. Resolve by direction: vertical/press = read, horizontal = dismiss.

Rule 2 · The whole notice is the copy button

You copy an error for exactly one reason: to give it to somebody — a colleague, an issue, an agent. So the unit of copying is not the sentence on screen, it is everything needed to act on it. And the target should be the entire card, because the current 13 px icon is the smallest thing on the smallest surface at the worst moment.

  • The three context lines are the difference between a bug report and a shrug. They are all already in memory at post time; none require new plumbing.

Why tap-to-copy and not tap-to-open. The current card navigates to Activity on tap. But you are already looking at the notice — navigating throws away the thing you can see to show you a list containing it. Copy is the action that cannot be done any other way; make it the one the whole surface performs. Opening moves to the › chevron and the keyboard.

Rule 3 · Dock it — a notice must never cover anything

Floating over content is why a notice feels like an interruption and why dismissing it is urgent. Instead: a strip that lives below the top bar at 3 px, grows to a line when there is something to say, and to a card when you touch it. It occupies layout — so it can never sit on the composer, the transcript, or a control.

Rule 4 · Review without leaving — pull the strip

“I cannot review what was just popping” has a literal answer: put the last few notices behind the strip they came from. Drag it down (iOS) or click it (macOS) and the recent ones unroll in place; let go and they roll back up. No route, no dialog, no navigation away from what you were doing.

5 · The structural move — failures belong in the conversation

makit is a chat app. It already owns a surface that is durable, timestamped, infinitely scrollable, selectable and copyable, and that you already scroll to remember what happened: the transcript. When a failure belongs to a session, the strongest version of “reviewable and copyable” is not a second record — it is a row in the first one.

Notice kindExampleWhere it goes
Session-scoped failure worktree create/delete, session quit, send failed, port kill refused Transcript row + strip flash. The agent’s own transcript is where you will look, because that is where you asked for it.
Global failure pair failed, server unreachable, push registration Strip + record only — there is no conversation it belongs to.
Trivial success copied URL, killed a port, archived Strip line, 3 s, no transcript row. These must stay cheap.
Agent asks you something askUserQuestion Already inline (SPEC-25 ask_card.dart) — precedent for this whole idea, and proof the pattern reads well.
  • The precedent is shipped. SPEC-25 already puts a machine-generated, interactive card in the transcript and settles it into a quiet resolved state. A failure row is the same shape with a smaller ask.
  • It makes “Retry” natural. Retry in a floating toast is a race against a timer; retry on a transcript row is just a button that is still there tomorrow.
  • The transcript is server-backed; these events are client-only (SPEC-48 D9: nothing persisted). So the row is local and ephemeral — it survives scrollback but not a relaunch, and it must be visibly the app talking (the makit label), never mistaken for agent output.
  • Pollution risk is real. Strictly failures and warnings that the user caused by an action in that session — never progress, never success, never lifecycle. Get this wrong and the transcript becomes a log.
  • Needs a decision on ordering when the transcript is mid-stream. Simplest correct answer: append at the current tail, never interleave into history.

Three keys, and the pointer rules

CHEAP
InputDoesWhy it matters
⌘⇧Ccopy the newest notice, with context The complaint verbatim: something flashed, you want it on the clipboard. Works whether or not the card is still on screen — it reads the record, not the pixels.
⌘⇧C ×2copy the last 10 as a report Press it again within a second and you get the sequence. Same key, escalating scope — no second shortcut to remember.

right-clickthe copy-format menu (Rule 2) Desktop users look for this first; there is nothing there today.
  • ⌘⇧C is the whole feature for a keyboard user — and it is perhaps 20 lines, because StatusCenter already holds the events and already knows how to format them for the clipboard.
  • It also makes the notice accessible: a screen reader announcing a card that disappears in 4 s is a joke; one that can be re-read and copied on demand is not.
  • Shortcut collisions must be checked against the composer and the existing desktop map (shortcuts_section.dart) before claiming ⌘⇧C.

The iOS parallel is the drag in Rule 4 plus touch-and-hold in Rule 1 — both gestures the platform already teaches, neither needing a visible control.

The shape of the fix. Rules 1–3 are under 80 lines together and between them kill both complaints outright — I would do those before touching layout. Rules 4–6 are the part that makes the notice stop feeling like an interruption: it never covers anything, it is always in the same place, and the last few are always one gesture behind it.

What is unchanged. SPEC-48’s StatusCenter, the severity model, Activity, and the OS-notification layer all stand — this is the presentation of the notice, not the record behind it. And nothing here re-opens the bottom-centre slot: that belongs to the composer.

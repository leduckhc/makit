Composer footer — give the controls the space they need — SPEC-40

Every number on this page was measured in a Flutter widget test at 375 pt with the real widgets and the real config-option shapes each adapter emits — not estimated, and not from the earlier SPEC-37 sketch, which turned out to describe a session shape no adapter produces.

⚠ What SPEC-37 got wrong. It flagged "a 3-config-pill pi session needs 279 pt of a 267 pt budget" and drew three pills (Sonnet, Sandbox, Approval). No shipping adapter emits that: pi advertises model + thought_level, codex adds an optional model_config, and all of those fold into the single model pill; a modes-only ACP agent gets one synthesised mode pill. So the real footer has one pill, and the sandbox/approval row was hypothetical. The problem is real, but it is not crowding — it is that the one pill is starved.

The root cause

Every footer action gets an equal-share Flexible, so a 36 pt ring reserves half the row.

today Flexible — config pills · 50% Flexible — usage ring · 50% (uses 36 pt) [+]send
needed Expanded — config pills · all that is left ring 36 pt [+]send

Flexible defaults to FlexFit.loose: the ring is allowed half the row, lays out at its natural 36 pt, and the remaining ~95 pt is not redistributed. The pill is capped at half a row it is the only real occupant of.

Degradation ladder

In order. Each step is only taken if the row still does not fit.

#StepWhy this order
0Space by need: pills Expanded, ring/[+]/send intrinsicStructural. Alone it ends the overflow and multiplies the label by ~2.5×.
1Model label drops the provider/ prefixpi-acp sets name = "provider/name". The provider is not what you check mid-turn, and the picker sheet still shows it in full.
2Read-only chips hide — deferredThey are decoration; the sheet shows the same values as live controls. Not built: after step 0 the chip fits at 375 pt (46 pt measured) on every shape an adapter actually emits.
3Standalone pills collapse into ⋯ N → sheet — deferredSame SPEC-31 pattern as the model pill. Not built: no shipping adapter emits a standalone option, and step 0 already makes that shape overflow-proof rather than merely narrow. Trigger to build it: an agent that ships ≥1 standalone option.
—Never: ellipsize the model name to fewer than a readable stub, hide the ring, or scroll the rowScrolling would push the ring off-screen, and the ring exists to be glanceable.
✓ Why not a single all-in-one config pill. It was considered and rejected: it fits trivially, but it hides mode — the one option that changes what the agent is allowed to do — behind a tap on every width, including the desktop panes that have 700 pt to spare. The ladder above degrades only when it must, so a wide pane keeps every control visible.

Only steps 0 and 1 are being built. Steps 2 and 3 address a session shape no adapter emits today, and step 0 turns that shape from an overflow into merely a narrow row, which is a legitimate state. Building them now would be speculative; the trigger for each is recorded above.

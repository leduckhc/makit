Docs — preview the HTML and Markdown that live in the repo — SPEC-46 draft

This repo holds 27 mockup boards, 70 spec & plan markdowns, and a shelf of architecture docs. They are the primary artefacts of the work — and they are the one thing makit cannot show you. Today you leave makit to read them: Finder → browser on the Mac, or "hey, open a port for me" on the phone. The fix is not a file browser. It is the Ports pattern applied to documents: makit already knows which worktree owns what, already streams live snapshots, already renders markdown, and already has an authenticated HTTP surface. Four options below, then a recommendation.

The two paths that exist today, and why both are bad.
Desktop: ⌘-tab to Finder → find mockups/ → double-click → the file opens in whichever browser is default, detached from the branch it belongs to. Open two branches' versions of the same mockup and you cannot tell the tabs apart.
Mobile: ask the agent to start python3 -m http.server, wait, get a 100.x:8765 URL, leave makit for Safari, and lose the link the moment the agent's session ends. The port then lingers in the Ports screen as an orphan — we built a whole feature to clean up the mess this workflow makes.
✓ Two facts make this much cheaper than it looks. (1) Markdown is already solved. flutter_markdown_plus is a dependency and chat_message.dart already renders styled markdown with a code-block builder — a spec file is the same content type the transcript renders all day. It needs no new dependency, no HTTP, no webview: the file is <100 KB, so it rides the existing WSS channel as text. (2) HTML is self-contained. Every board in mockups/ is a single file with inline <style> and inline SVG — zero external assets. So "serve a mockup" means serving one file, not resolving a dependency graph.
⚠ The one genuinely new capability: rendering HTML. There is no webview package in app/pubspec.yaml — url_launcher is the only way the app currently opens a URL, and it leaves the app. Worse, the media route's URL (https://100.x:7777/media/…) cannot be opened in Safari at all: the cert is self-signed and fingerprint-pinned inside pinned_http.dart, so a browser gets an untrusted-cert wall. Card 6 settles this with a decision table. Everything else in this document is transport we already own.

1 · The index — what counts as a "doc", and what must never be served

P1shared foundation

All four options consume the same snapshot. Build this once and the options become interchangeable UI.

Git-aware, not a fixed allowlist (D1 rev 2)

A file browser is the wrong primitive. makit asks git: git ls-files --cached --others --exclude-standard — tracked and freshly-written untracked docs both appear, and anything in .gitignore (e.g. secrets.md) is excluded for free. D2's dot-directory rule drops .agents/skills/ without an opt-in.

Fallback when git cannot answer: walk mockups/, docs/, and root *.md.
Narrow per project with .makit/docs.json roots.
Hard exclusions — security, not tidiness
Serving a worktree is serving secrets. A naive static root hands out .env, .git/config (which holds tokens), and private keys. Non-negotiable rules: extension allowlist (.md, .html only) · canonicalise then prefix-check against the worktree root · refuse symlinks that escape · skip dotfiles and dot-directories · never .git/, node_modules/, build/, .dart_tool/, dist/, coverage/ · read-only, size-capped at 5 MB.
The DTO — modelled on PortDTO, same tolerant-parse discipline
// protocol.ts — snapshot identity only, never persisted (cf. PortDTO D6)
interface DocDTO {
  key:         string;   // "<worktreePath>:<relPath>"
  relPath:     string;   // "mockups/open-ports.html"
  title:       string;   // <title> | first "# H1" | basename — a HUMAN name
  kind:        "md" | "html";
  bytes:       number;
  modifiedAt:  number;
  worktreePath:string;
  sessionId?:  string;   // the session that last wrote it → "made here"
  changed?:    boolean;  // differs from branch merge base (D5) — absent when undetermined
  docStatus?:  string;   // parsed "**Status:** Draft" — free signal, this repo writes it
}

Titles are extracted, never filenames. 2026-08-07-SPEC-44-ports-forward.md is unreadable on a 375 pt row; "SPEC-44 — Ports P4: forward a loopback port to the phone" is the actual name of the thing. Same for HTML: <title> already says "makit — Ports: what's listening, and whose branch owns it". This single decision is most of the perceived quality.

Wire & cadence. docs.watch {on} ref-counted exactly like ports.watch, and no polling — worktree_watcher.ts already watches the tree, so a debounced (400 ms) re-index on change is enough. Reads: docs.read returns markdown text over WSS; docs.publish mints a short-TTL grant for HTML; docs.unpublish / docs.grants manage it. No new event kind — snapshots stream on the existing channel.

P1transport, not UI

No renderer, no dependency, perfect fidelity. Real Safari, real JS, print-to-PDF, and it works on a device that has never paired with makit.

Why the tailnet address: The doc listener binds lazily to makit's tailnet IP on first publish and releases at zero grants (D10 rev 2) — no tailscale serve, no always-on port. Plain HTTP is fine: WireGuard already encrypts the tailnet, and the URL is never typed — it is tapped, copied, or scanned. The QR is the sleeper feature — it puts the board on an iPad or a colleague's laptop in one scan, and makit already owns QR rendering from device pairing.

⚠ Corrected during spec review (SPEC-46 D9). This frame first drew /docs/<branch>/<path>. That cannot work: a URL that must open in Safari cannot carry a bearer header, so the capability has to live in the path — /docs/<grantId>/<relPath>, 32 bytes of CSPRNG. The grantId is the secret, which is exactly why publishing is explicit, expires, and has a Stop sharing button. A wrong or expired id returns 404, not 403 — 403 would confirm the file exists.
The reach vocabulary — reuse SPEC-41's words, do not invent new ones
pinned
Served over makit's own authenticated channel to a paired device only. Never leaves the app. This is what Options A/B/C use.
tailnet
Reachable by anything in your tailnet, browser included. The tailnet ACL is the security boundary, not makit. Explicit, revocable, time-boxed.
lan
Anyone on the Wi-Fi. Offered only as a fallback, always labelled, and it dies when the phone leaves the network.
✓ Sharing is a verb with an off switch. Every published doc is a grant — 30-minute TTL, idle-reaped, listed in one place with Stop sharing. Reuse SPEC-44's grant record verbatim; the difference is only that the target is a file, not a port. Publishing must never be implicit, and the app must be able to say "3 docs are currently shared".

Honest weakness: it leaves makit. You lose the branch context, the back-swipe, and the changed-on-this-branch framing that makes the catalog worth having. Perfect as an escape hatch and as P1's answer for HTML — wrong as the only answer.

Per client, not per server. One server can hold a desktop app on loopback and a phone on the tailnet at the same moment, so “local” is a property of the connection — which the server already computes (isLocal, from the remote address). A local client gets Open in browser and never needs Tailscale running; a remote client gets Publish & open and the grant machinery (D9/D10/D15) exactly as before. Publish stays available locally as a secondary action — that is how you get a board onto your phone from the desk. Opening on the host is a server capability, so it is gated to local clients and still routed through the one path boundary (D2) — a remote client asking for it is refused, not served.

7 · Recommendation — one index, three phases, no wasted work

chosen

The options are not rivals; they are three containers around one preview widget. Ship the cheap halves first.

PhaseShipsNew dependenciesThe pain it removes
P1 The index (Card 1) + Docs screen (Option A) + markdown preview in-app (free) + HTML in a real browser: opened on the host when the viewer is on the same machine, or published to the tailnet for another device (Option D, with the grant list and Stop sharing) none Both of today's paths die. Specs and plans read natively on the phone; a mockup is one tap from a real browser with no port to ask for and no orphan left behind.
P2 Artifact cards + inline chips in the transcript, Quick Open ⌘⇧O / pull-to-search (Option B) none Removes navigation entirely for the 80 % case — the doc the agent just wrote, reachable where it was announced.
P3 Webview + pinned loopback proxy (shared with SPEC-44) → HTML in-app, then Canvas with live reload (Option C) webview_flutter The design-review loop: edit, watch it change, steer — without leaving makit.
The three rules that keep the phases cheap

1 · The preview is a widget, not a route. DocPreview(doc) must render identically inside a bottom sheet (A), a modal from a chat card (B), and a split pane (C). Build it as a route and P3 rewrites P1.

2 · One index, many surfaces. Screen, palette, chat chip, and popover all read the same docs.snapshot. If a second lookup path appears, they will disagree — the mistake Ports avoided by having exactly one snapshot.

3 · Reuse SPEC-44's grant record. Publishing a file and forwarding a port are the same security object with a different target. Two grant models means two revocation bugs.

Open questions worth answering before P1

a · Dirty in the working tree or differs from the merge base? Settled: changed means differs from the merge base (D5). A dirty-tree flag would go green the moment you commit, which is backwards.

b · Should the Docs screen include archived worktrees? Ports says yes-with-an-orphan-badge. A removed worktree's mockups are gone from disk, so probably no — but the history store makes it answerable.

c · Is .agents/skills/**/SKILL.md in the default roots, or opt-in? 22 files of machine-facing prose could drown 27 boards you actually look at.

d · Thumbnails: server-side Chrome is another binary dependency on the host. Worth it for the transcript card, or is the kind glyph enough for P2?

✓ Nothing here is new chrome. The Docs screen is ports_screen.dart's app bar + filter row + grouped list. The row is .port with a narrower lead. The sheet is port_detail_sheet.dart. The glyph is a trailing-column icon button in the slot SPEC-41 already settled. The transcript card is the media-attachment card with a different body. The QR is the pairing QR. The grant is SPEC-44's grant. The only genuinely new thing in the whole spec is the doc index — and the watcher that feeds it already runs.

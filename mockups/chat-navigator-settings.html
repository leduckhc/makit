A style picker plus per-style options, in the app's real settings language (SettingsSectionHeader + SettingsGroup rows, macOS-grouped-list idiom). Two presentation treatments below — both are live and drive the preview pane on the right.

Progressive disclosure is the whole trick here. Five styles × 2–3 options each is 13 controls; showing them all at once would make this the noisiest section in Settings. Only the selected style's options render — the rest collapse to one line each.

1 Expanding radio list recommended

Each style is a row with a one-line description; picking one expands its options inline underneath. You can read all five choices and their tradeoffs without clicking anything.

Honest cost: this ships five navigators, not one. Each needs its own tests, its own mobile story, and stays on the maintenance bill forever.
Cheaper middle ground: ship Rail + Off + density now, and add styles to this same picker later — the preference is forward-compatible if you decode unknown ids to the default.

2 Segmented control + options block

Compacter: styles collapse into one SegmentedButton (the pattern already used for theme mode in appearance_section.dart), with the chosen style's description and options below. Costs less vertical space; hides the tradeoffs until you click each one.

Which treatment? 1 makes the decision informed (you see what "Outline" means without selecting it); 2 fits the existing Appearance-section rhythm and stays short. 1 is better for a choice you make once; 2 is better for one you toggle often.
The preference schema is identical either way — only the widget differs.

schema Preference entries this needs

Declared in app/lib/desktop/settings/prefs/preference_entries.dart and added to kPreferenceEntries — no controller or provider changes, and "modified / reset" falls out of the diff-only persistence for free.

// The style picker. Unknown ids decode to null → falls back to the default,
// so a downgrade (or a style we later remove) can never corrupt the pane.
enum MessageNavigatorStyle { off, rail, scrubber, palette, breadcrumb, outline }

const PreferenceEntry<MessageNavigatorStyle> messageNavigatorStylePreference =
    PreferenceEntry(
      id: 'chat.navigator.style',
      defaultValue: MessageNavigatorStyle.rail,
      encode: _encodeNavigatorStyle,   // value.name
      decode: _decodeNavigatorStyle,   // name lookup, null when unknown
    );

// ── rail ──────────────────────────────────────────────────────────
const ... railTickSpacingPreference   = /* int, 6 */  'chat.navigator.rail.spacing';
const ... railRipplePreference        = /* bool, true */ 'chat.navigator.rail.ripple';
const ... railEncodeLengthPreference   = /* bool, true */ 'chat.navigator.rail.encodeLength';
// ── scrubber ──────────────────────────────────────────────────────
const ... scrubLiveScrollPreference    = /* bool, true */ 'chat.navigator.scrub.liveScroll';
const ... scrubTimestampsPreference    = /* bool, true */ 'chat.navigator.scrub.timestamps';
// ── palette ───────────────────────────────────────────────────────
const ... paletteSearchAllPreference   = /* bool, false */'chat.navigator.palette.searchAll';
// (the shortcut itself lives in the Shortcuts section's keymap, not here)
// ── breadcrumb ────────────────────────────────────────────────────
const ... crumbAutoHidePreference      = /* bool, true */ 'chat.navigator.crumb.autoHide';
const ... crumbCounterPreference       = /* bool, true */ 'chat.navigator.crumb.counter';
// ── outline ───────────────────────────────────────────────────────
const ... outlineHideToolsPreference   = /* bool, false */'chat.navigator.outline.hideTools';
const ... outlineShowCountsPreference  = /* bool, true */ 'chat.navigator.outline.showCounts';
Two schema notes.
· Per-style options are flat, not nested — one entry each, namespaced by style. Nesting them under the style would mean a custom codec and would lose per-row "modified" tracking.
· Options for a non-selected style stay persisted. Switching Rail → Outline → Rail returns you to your spacing, which is why the picker must not clear them.
· This is a shared setting (mobile renders the same transcript), so it belongs in the synced preference set — but rail and breadcrumb have no touch story. Mobile must coerce hover-only styles to scrubber at read time rather than store a second value.

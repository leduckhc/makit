Ports — what's listening, and whose branch owns it — SPEC-41 draft

A listening TCP port is treated as an attribute of a worktree, like its diff stat or its PR. Ownership comes from the process cwd plus a ppid ancestry walk, so :5173 reads as “the Vite server feat/open-ports is running” — not “some node process”. The row itself stays quiet: one glyph says something is listening, and the numbers, health and actions live in a popover (desktop) or a two-step sheet (mobile). Plus a global Ports screen and the menubar. Palette is the app's real M3 dark scheme (lib/app/theme.dart).

Build phasing (SPEC-41). P1 ships now — scan + attribution + health, the row glyph, the desktop popover, the two mobile sheets, tooltips. Read-only: Open and Copy URL are the only actions, so nothing in P1 signals a process. P2 global Ports screen, orphans/collisions, docker, menubar. P3 kill + suggested port. P4 forward-to-phone + watched ports. Frames below are tagged; a P2/P4 frame exists so the P1 shapes don't have to be redesigned to admit it. Spec: docs/specs/2026-08-06-SPEC-41-open-ports.md.
⚠ Rev 2 — what two code reviews changed. No wss/protocol label (a plain GET / cannot produce a valid HTTP 101, so the pill now shows whatever status makit's own port really answers). No kind guessing and no cpu/memory — rows show the real command. Probing is narrowed to ports owned by one of your worktrees, minus databases: pointing GET / at every listener on the machine would poke X11, VNC and SMTP and would render a healthy HTTPS server as broken. lan/tailnet became exposed for wildcard binds, because 0.0.0.0 is reachable from every interface — tailnet now means an exact address match. Docker rows are tagged P2. The desktop hit target is 22 × 16 pt, not 22 × 22: Flutter clips hit-testing to the parent's box, so the earlier "overflow into neighbouring padding" claim was not implementable.
✓ Nothing here is new chrome. The glyph is a trailing-column icon button like the row's existing + — nested inside the row's own InkWell, exactly as … and + already are (see §4). The desktop popover is the GithubBudgetButton / repo-hover pattern; the sheets are the pr_sheet.dart pattern. The global screen is the archived_screen.dart pattern (app bar + filter row + grouped list). The menubar entry already exists. Every frame below is an instance of an existing makit convention.

3 · Tooltips — every terse token owns a sentence

P1rule

A pill short enough to fit (200, refused, exposed) is a label, not an explanation. One string per token, used by the desktop tooltip, the mobile long-press bubble and the screen-reader label — never three drifting copies.

4 · Who owns the click? — the row already has a handler

P1conflict, resolved

On macOS the worktree row is selectable, and on iOS its tap folds the sessions. The glyph must take its click without stealing the row's — the same problem the repo header already solved.

✓ Precedent, not invention. mockups/repo-hover.html (AFTER) puts … and + inside the repo header's single full-row InkWell: the row hover paints beneath them, each nested button gets its own small hover circle, and clicking one does not trigger the row. The ports glyph is a third instance of exactly that arrangement — it sits in the same trailing column as the row's existing +, which already swallows clicks today.
Hit-target map · macOS sidebar row (hovered)

Every “unchanged” row is the point. The feature adds two gestures (glyph click/tap, glyph right-click) and re-uses one (hover). If any existing row behaviour had to move, the glyph would be in the wrong place.
⚠ The cost of this order, stated plainly. Ports now sits between two other targets, so on iOS a thumb aimed at the gap can fold or start a session instead. That is the price of keeping + on a fixed right edge, and it's the right trade: + exists on every row, ports and the caret do not, so the stable anchor should be the one that's always there. Mitigations, in order: (1) 8 pt gutters on phone instead of 4 — the column has room because most rows draw at most two of the three; (2) both neighbours are non-destructive, so a mis-tap costs one tap to undo (fold back, or dismiss the new-session sheet); (3) most rows have no caret at all (it only exists when the worktree has sessions), which leaves ports with a blank slot on its left. Worth measuring on device before shipping.
Rejected here: making the glyph hover-only on desktop (no keyboard path, and a hover-only surface that holds a Kill button is indefensible); putting the glyph outside the row to dodge the conflict (breaks the alignment grid, and the association with its branch); putting it last, outboard of + (isolates the glyph nicely, but moves the one control every row has — a worse trade); and ⌥click-to-open (undiscoverable for the primary action of the feature).

10 · Considered and rejected

refnot building

Recorded so the choices above read as decisions rather than defaults.

  • Port numbers on the worktree row. Tried as a fourth repo_chips.dart pill (🔌 5173 9787). It competes with the diff and PR chips for the one line that matters, and it answers a question you don't have while scanning eight worktrees: at row level you want whether, not which. Replaced by the single glyph in §1.
  • Buttons inline in the mobile list. A Kill next to a port in a scrollable list is a fat-finger trap during a flick. Actions moved into the second sheet, destructive one last, past a labelled divider.
  • A hover-only desktop popover holding buttons. Unreachable by keyboard and fragile under a trackpad — leave the glyph and your click target evaporates. Hover kept for the glance, click-to-pin added for the actions: one surface, two levels of commitment.
  • Ports as a column in the repo card header. The header already carries name + actions; a port count there answers a question nobody asks at repo level (“my repo has 5 ports” is meaningless — a branch having them isn't).
  • A dedicated tab per repo. Doubles navigation depth for the rare case. The single global screen with a This repo filter covers it in one tap.
  • Always-on port notifications. Dev servers restart constantly; this would be an unusable firehose. Watching is per-port opt-in.
  • Continuous background polling. lsof is not free (hundreds of ms, worse with network mounts). Poll only while a client is subscribed to the ports view — same discipline as repo_service.ts's “occasional, not per-event”.
  • Showing every socket (established connections, UDP). Listeners are the thing you own; the rest is traffic. A full netstat view would bury the four ports you care about.
  • Auto-killing idle servers. Too clever, too destructive. Offered as a reviewable “Kill all orphans” list instead, never automatic.
  • Reusing the diff/PR chip shape verbatim with no glyph. Bare numbers on the meta line read as diff counts — one of the reasons the numbers left the row entirely.
Suggested phasing. P1 scan + attribution + PortDTO on the wire + the row glyph, the desktop popover and the two mobile sheets (read-only: Open / Copy / Logs, no kill). P2 global Ports screen with filters, orphan/collision detection, port history table. P3 actions: kill (confirm-gated), kill-all-orphans, suggested port. P4 forward & open, watched ports + notifications. Each phase is independently shippable and useful on its own.

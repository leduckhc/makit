How long did that take?

Four scopes, four different questions. Tool call and thinking are attribution ("what ate the two minutes"). Turn while running is a stuckness question ("is it alive"). Session is a cost/effort question. The same number rendered the same way in all four places would answer none of them well, so each section below is judged on its own.

Reading this board: emoji stand in for the app's Phosphor icons, so icon weight and optical alignment cannot be judged here — only placement, size and text. Greys are the real theme.dart tokens, so contrast can.

⚠ Three data facts to hold onto.
  • Every event already carries ts (server/src/protocol.ts:387) and every ChatItem keeps it (chat_items.dart:31) — so durations are derivations, not new telemetry.
  • But the end timestamps are dropped on the floor today: ToolCallItem.copyWith and ThinkingItem.copyWith both re-use the start ts. Tool + thinking durations need one field each (endedTs / lastTs). No wire change.
  • session.status is a logged event (session.ts:437), so running → idle turn edges are already in the transcript stream. Only session age needs the wire touched: Session.createdAt exists and is persisted (session.ts:147) but is missing from SessionDTO.
Two semantics decisions the pictures can't make for you.
  • Turn = wall clock, or agent work? awaiting-approval / awaiting-input emit status events inside a turn. So "you kept it waiting 4m" is separable from "it worked 2m" — and a naive "running until not-running" would end the turn at the approval gate and report nonsense. Variants §4B/§4C show both readings.
  • Session = age, or work? A session opened 3 days ago with 4 minutes of agent time is described honestly by two numbers and lied about by either alone. §5 shows one-number vs two-number.

8Considered and rejected

Recorded so nobody re-proposes them in review.

ideawhy not
Absolute clock per row (14:02:11)answers "when", not "how long". A permanent column for a fact you almost never need — and it's already in §1D's tooltip.
Progress bar / ETA on a running toolno denominator exists. Same argument that makes ContextUsageRing refuse to render without a known window: a bar means "share of a whole", and there is no whole.
Colour-coding every duration by speedthe palette is one hue plus tuned status semantics (DESIGN.md). A green/amber/red gradient across every row spends the entire colour budget on a secondary fact. Only §2B's "past 60s" escalation is a genuine status.
Sparkline of turn durations in the transcripttrend belongs in the §5B rollup (median turn), not repeated inline. The perf dashboard is the place for graphs.
Per-row Timer.periodicmeasured: animated widgets must be inside the viewport and one shared clock beats N tickers. Use PulseClock at 1 Hz; only the tail row ticks.
Announcing the live counter to screen readersa per-second live region is unusable. Duration belongs in the row's semantics label on completion ("ran for 48 seconds, succeeded").

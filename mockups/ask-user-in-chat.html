Ask-user question — in the chat, not a drawer

Today an askUserQuestion (server srv.request) is presented as a blocking modal dialog over the whole app (AskWizard in srv_request_handler.dart). Proposal: render it inline as a transcript item, anchored where the agent asked, using the same option tiles + recommended badge + multi-select semantics — and leave the resolved answer in the chat as history (the existing _AskUserQuestionRenderer already shows the answered form). Rendered with the app's real M3 dark palette inside the readable-width chat column.

ABefore (modal drawer) → After (inline in chat)

The modal hides the conversation and its own context (which tool/agent asked, what came before). Inline keeps the question in the flow, scrolls with history, and reads as part of the turn.

E“Type a different answer” — inline in the card (not a dialog, not the composer)

Proposed change to decision #2. Today “type your own” either hands off to the main composer or (for pi's freeform fallback) pops a modal input dialog. Instead: tapping Type a different answer reveals a text field inside the ask card itself, with its own Send. The composer stays paused throughout; nothing leaves the card. On submit it resolves like any other answer and settles into the quiet resolved card (§D).

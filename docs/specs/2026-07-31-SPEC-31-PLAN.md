## Design seams (decided)

- **Category partition** (Makit UX policy, conservative): `modelScoped =
  {model, model_config, thought_level}`; everything else (incl. `mode`, unknown,
  `_`-prefixed) is **standalone**. No `model` option present → skip the whole
  menu path, render exactly as today.
- **Active-row-only flyout** (decision (a)): only the active model's Recent row is
  expandable; non-active rows select-only (selecting makes it active, revealing
  its flyout).
- **Chips are read-only labels**; the pill tap opens the menu. `thought_level` →
  `ThinkingSignal`; each `model_config` select → its current value; boolean shown
  only when true.
- **Flyout dispatches the existing `configOption` action** on the live active
  model; composer re-renders wholly from the re-emitted list (never merges).

## Lanes

```text
Lane 1 (partition + footer chips)     → serial, FIRST (defines the model API)
Lane 2 (recent store)                 → parallel with Lane 1 (independent)
Lane 3 (menu: rows + search + state)  → after Lane 1 + Lane 2
Lane 4 (flyout column)                → after Lane 3 (SAME FILE + shared row/menu state)
Lane 5 (new-session parity)           → after Lane 3 + Lane 4
   └── all merge → Green gate
```

Lanes 1 and 2 are independent and parallel. Lanes 3→4→5 are **serial**: they
share `model_picker_menu.dart` and the same row/menu-state contract (the active-
row affordance is Lane 3; its flyout is Lane 4 behaviour on the same widget), so
parallelising them would only conflict. Wire is frozen throughout.

### Lane 1 — Category partition + footer chips
**Owns:** `composer_selectors.dart` (`ComposerConfigOptions`, a new pure
`partitionConfigOptions`, footer chip widgets), its tests.

TDD:
1. `partitionConfigOptions(List<SessionConfigOption>) → (model?, modelScoped[],
   standalone[])`. Pure, table-tested: `mode`/unknown/`_x` → standalone;
   `model_config`/`thought_level` → modelScoped; missing `model` → null (skip).
2. Footer model pill: avatar + active model name + read-only chips from
   `modelScoped` (reasoning bars via `ThinkingSignal`; each `model_config`
   current value; boolean only when true). Tapping opens the menu (Lane 3).
3. Standalone options render as today via existing `ConfigOptionPill`, after the
   model pill. **No `model` category option → this widget renders exactly today's
   `ConfigOptionPickRow`** (the flat pill row) — *not* the legacy triple (that is
   only the empty-`configOptions` path).
4. Widget tests: chip content per category; `mode` stays separate; absent `model`
   category → today's `ConfigOptionPickRow` unchanged; narrow-width clip (no overflow).

### Lane 2 — Recent-models store
**Owns:** new `app/lib/store/recent_models.dart` (+ provider), its tests.

TDD (mirror `preferences_controller_test`):
1. `RecentModelsController` over `shared_preferences`, single JSON key
   `recent_models` = `{agentId: [modelValue,…]}`. Corrupt/absent → empty.
2. `recordSelect(agent, value)`: prepend, dedup, cap at `kRecentModelsMax` (7),
   most-recent-first. `recentModels(agent)` reads. **Recorded on the user's
   selection gesture** (there is no action-success signal — actions are
   fire-and-forget), so a select optimistically updates recents immediately.
3. Agent-scoped isolation; ephemeral (null prefs) variant for tests/default,
   mirroring `PreferencesController.ephemeral()`.

### Lane 3 — Model picker menu: rows + search + state
**Owns:** new `app/lib/ui/composer/model_picker_menu.dart` (rows, search states,
menu/row state, the injected `values`/`onPick` API), its tests. Consumes Lane 1
partition + Lane 2 store.

**Injected-state API (so the same menu serves live + draft):** the menu takes
`activeModel`, `catalog` (flat + flattened groups), `recent`, a `values` map
(id→current value) and an `onSelectModel(value)` / `onPickOption(id,value)`
callback — exactly mirroring how `ConfigOptionPickRow` already injects
`values`/`onPick` (composer_selectors.dart:329). Live composer feeds re-emitted
`session.meta` values + session actions; the draft feeds `_picks`
+ local setState (Lane 5). The menu itself owns no session knowledge.

TDD:
1. Empty query → **Recent** rows (from store ∩ catalog, active row marked `✓`),
   each: avatar + name + chips; only the **active** row shows `›`.
2. Non-empty query → flat filtered full catalog (`model.options` +
   flattened `model.groups`), selection-only, case-insensitive match (reuse the
   `showSearchableListSheet` matcher semantics).
3. Selecting a value → `onSelectModel(value)` (caller records recent + dispatches
   `configOption`); selecting the **active** value is a **no-op** (no callback,
   no recent mutation).
4. **Interaction:** tap a *non-active* recent row → exactly one `onSelectModel`;
   feed the replacement `configOptions` → that row becomes active and is now the
   only one exposing `›`.
5. Empty catalog / no `model` option → menu never opens (Lane 1 skip).
6. Host: desktop `MenuAnchor`/overlay panel; mobile the existing sheet. Widget
   tests assert content for both states + group flattening.

**Desktop-host risk (not a trivial swap):** today the shared composer opens
*bottom sheets everywhere* (`showSearchableListSheet` L29, generic sheet L461),
including desktop. A desktop `MenuAnchor` overlay is a **new pattern** here
(precedents exist: `open_in_ide.dart`, `pr_bar.dart`). Budget for overlay sizing,
dismissal/focus, and flyout collision in narrow desktop panes. **Fallback:** if
the overlay proves fiddly, render the menu as a sheet/dialog on desktop too
(same content) — the content widget is host-agnostic by design above.

### Lane 4 — Flyout column (active model)
**Owns:** the flyout column widget **in the same `model_picker_menu.dart`**
(serial after Lane 3; shares its row/menu state), its tests. Consumes Lane 1
`modelScoped`.

TDD:
1. Renders one segment per `modelScoped` option in agent order: `select` →
   values stacked vertically, current marked (`✓`+accent); `thought_level`
   header carries `ThinkingSignal`; `boolean` → single toggle row.
2. A change calls `onPickOption(id,value)` (live: dispatches `configOption` for
   the active session; re-render from the re-emitted list, never merged).
3. **Option removed** from the re-emitted list while the flyout is open → no
   crash; flyout reflects the new list.
4. Desktop anchored beside the active row; mobile pushed as a second sheet page
   with `‹` back. Same column widget, two hosts.

### Lane 5 — New-session dialog parity
**Owns:** `worktree_starter.dart` (swap `ConfigOptionPickRow` model rendering to
the new menu for the draft), its tests.

TDD:
1. Pre-session draft uses the same menu + (draft) flyout via the injected
   `values`/`onPick` API (Lane 3), backed by **local pending picks** (`_picks`
   with fallback to each option's `currentValue`; no live session, no re-emit).
   Picks apply at launch unchanged from SPEC-27.
2. Non-model standalone options in the draft still render as today.
3. Widget tests: a draft selection updates the local chips/flyout **without**
   touching recents or dispatching a live action; the launch payload carries the
   picks.

## Risks (from spec, plan-relevant)

- **Re-emit is a full replacement** — flyout/menu must re-render from
  `session.meta.configOptions`, never merge; disappearing options must not crash.
- **Footer width** — chips clip gracefully in narrow split panes.
- **Desktop/mobile fork** — one flyout column widget, two hosts.
- **No shadow state in C** — flyout only ever touches the live active model; the
  store holds only the recent list.

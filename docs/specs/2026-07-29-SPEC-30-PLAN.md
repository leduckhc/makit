### Lane 2 — `GroupsController` + commit sink + migration (decisions 2, 4, 8, 19)
**Owns:** `groups/groups_controller.dart`, `panes/workspace_controller.dart`
(constructor/persistence only), `desktop/desktop_app.dart`,
`test/desktop/chat/groups/groups_controller_test.dart`,
`test/desktop/chat/workspace_controller_test.dart` (persistence cases move out)

- **Commit-sink refactor** (spec § "the load-bearing bet"): replace
  `WorkspaceController`'s `SharedPreferences` with an injected
  `void Function(WorkspaceState)?` sink; `.ephemeral()` keeps a null sink.
  **Every tree-mutation method keeps its body.**
  - The sink is **fire-and-forget and must not throw**. Today `_persist()` is
    `async` inside a `try/catch` precisely so "a failed write must not crash the
    app or surface as an unhandled async error"; that guarantee moves to the
    groups side, which swallows write failures the same way.
- `GroupsController` owns `{ v, groups, activeGroupId, recentlyClosed }`,
  persists the whole thing under `kGroupsPrefsKey`, and supplies the sink
  (`(tree) => commitTree(activeId, tree)`).
  - **Versioned payload:** `v: 1`. This lane exists because an unversioned blob
    had to be migrated; the replacement must not repeat that. An unknown `v`
    falls back to the fresh-launch state rather than throwing.
- Ops: `activate`, `openWorktreeGroup`, `newBoard`, `closeGroup` (worktree → drop;
  board → `recentlyClosed`, cap 10), `reopenBoard` (**filters dead members**,
  empty board still returns), `undoClose`, `addMember` (**converts** on
  out-of-scope explicit add → `<branch> +1`, original untouched), `removeMember`,
  `setLayoutOverride`, `reorderGroups`, `commitTree`.
- **Migration:** old `kWorkspacePrefsKey` blob → one board `Board 1`, preserving
  empty tabs verbatim (decision 21); any decode failure → the fresh-launch state
  below. Never throws, never wipes silently without falling back.
- **Fresh launch (decision 19), explicitly:** with no persisted groups, seed the
  worktree group of the **most recently active session**; with no sessions at
  all, seed an empty board `Board 1`. Tests: sessions present → their worktree
  group is active; none → `Board 1`.
- `desktop_app.dart`: build `GroupsController.load(prefs)`, derive the workspace
  controller from the active group's tree.
- **Acceptance criterion (hard):** the **38** tree-mutation tests in
  `workspace_controller_test.dart` pass **untouched**. If one needs editing, the
  refactor is wrong.
  - *Outcome:* held. The **7** tests of the old `persistence` group were rewritten
    in place rather than moved, because they turned out to cover two things that
    still belong to this layer: the **sink contract** (ephemeral = null sink,
    every mutation reported, a throwing sink cannot break a mutation, reads never
    commit) and the **decoder** (`decodeWorkspace`, which the migration reuses to
    read the legacy blob). Storage coverage is additionally in the groups suite.
    Net: 45 → 48 tests here, +28 in `groups_controller_test.dart`, none lost.

### Lane 3 — Membership, placement, prune, navigation (decisions 5, 6, 9, 15, 20)
**Owns:** `groups/group_providers.dart`, `groups/placement.dart`,
`desktop_session_prune.dart`, `desktop_auto_select.dart`,
`selected_session.dart` (reveal resolution — **hand to Lane 7 when done**),
`test/desktop/desktop_session_prune_test.dart`, `test/desktop/desktop_auto_select_test.dart`,
`test/desktop/chat/selected_session_test.dart`, `test/desktop/chat/groups/placement_test.dart`

- `groupMembersProvider(groupId)`: derived (`projectId` + `worktreePath` match)
  or curated, filtered to live sessions.
- **Placement** (decision 9) as a pure function taking the threshold as a plain
  `int`, so it needs nothing from Lane 4 beyond the value:
  `place(group, sessionId, {required int threshold})` — under *N* → new split;
  at/over *N* → new tab in the focused split; an override pins one answer.
  **Nothing ever re-arranges an existing tree.**
- Reconcile membership into a group's tree **without moving existing panes**:
  new members are placed, gone members are removed, nothing else shifts.
- Manual arrangement (split, close-split, tab drag) implicitly sets
  `layoutOverride`; the `Split | Tabs` toggle sets it explicitly and re-lays-out
  **once**, on that click.
- **Empty worktree group → the starter (decision 20).** Minting or activating a
  worktree group with no members seeds its tree's tab with the group's scope as
  the worktree hint, so `DesktopChatPane` renders `WorktreeStarter` rather than
  `EmptyPaneStarter`. (`_seed()`'s hint-less tab is why this is not free.)
- **Auto-select must become group-aware.** `desktop_auto_select.dart` currently
  calls `revealSession(mostRecentlyActive)` straight on the workspace controller,
  which under groups would inject a foreign session into the active tree —
  bypassing `addMember` and breaking decisions 4, 5 and 15 at once. New rule: it
  may only reveal a session **within the active group's membership**; if none
  qualifies it stays inert (it must never switch groups on its own).
- Extend the prune: a session absent from `sessions.snapshot` is unpinned from
  **every** board (decision 6) as well as having its tabs closed.
- Decision 15's session-click resolution (a → active group if already a member,
  b → its worktree group if open, c → any open board holding it, d → mint its
  worktree group) — and never `addMember`, so navigation can never convert.
- Decision 7's tail: deleting the active group's worktree focuses the
  neighbouring group tab.
- Tests: 3rd session → new split, 4th → tab (threshold 3); a manual split sets
  the override and placement follows it; the toggle re-lays-out exactly once; a
  new session on a scoped branch joins **without** switching the active group
  (decision 5); an archived session unpins from every board; each of a–d resolves
  and none converts; an empty worktree group renders `WorktreeStarter`;
  **auto-select with `feat/login` active and the newest session on `main` leaves
  the canvas untouched**; worktree deletion focus.

## Known follow-ups (not blocking; carried out of the lane work)

1. **The trailing `+ Add agent` region on a board's canvas** (decision 14, path a)
   was not placed: its home is `split_tree_view.dart`, which Lane 6 was forbidden
   to touch while Lane 8 owned it. The other three add paths (tab-strip `+`,
   sidebar quick-pin, drag-and-drop) are wired, so the capability is reachable —
   this is the *fourth* affordance, not the feature.
2. **`MembershipBar` overflows below ~420px** of canvas width (dragging the
   sidebar to its maximum). Lane 8 contained it at the strip layer (clip + min
   width) rather than editing another lane's widget; the real fix belongs in
   `membership_bar.dart` — it should degrade (drop the sentence, keep chip +
   toggle) instead of relying on a clip.
3. **A drag-and-drop widget test** for the conversion-on-drop path was dropped:
   the simulated `Draggable→DragTarget` accept did not fire reliably in the test
   harness. The conversion logic itself is covered at the controller level
   (`groups_controller_test.dart`), so the gap is in the gesture plumbing only.

# SPEC-41 — Implementation plan (P1, rev 2)

Spec: [`2026-08-06-SPEC-41-open-ports.md`](./2026-08-06-SPEC-41-open-ports.md) ·
Mockups: [`mockups/open-ports.html`](../../mockups/open-ports.html)

Ground rules (AGENTS.md): **failing test first**, SOLID/YAGNI, surgical diffs, match existing
style. Commands are the repo-supported ones from
[`docs/DEVELOPMENT.md`](../DEVELOPMENT.md) — `pnpm test` / `pnpm typecheck` in `server/`,
`flutter test --no-pub` / `flutter analyze --fatal-infos --no-pub` in `app/`. Two caveats worth
repeating because they cost real time: never `pnpm exec tsx --test` (it prunes devDependencies and
hangs — use `pnpm test`, or `node --import tsx --test <file>` for one file), and where `flutter` is
not on `PATH` use the absolute binary for your machine (AGENTS.md records `~/flutter/bin/flutter`
for the Linux VM).

D1–D7 in the spec are **locked**; there is no decision gate left in this plan.
P1 sends no signal to any process.

## Order (revised after review)

The contract golden is written **first** so there is a red test before any protocol code, and
the vocabulary precedes the glyph that imports it. App state depends on T1's frozen shape,
not on the server being finished.

```
T1 protocol + red contract test
   ├── server ──▶ T2 scan ─┐
   │                T3 proc ┼─▶ T5 attribute ─▶ T6 health ─▶ T7 service ─▶ T8 ws+wiring ─▶ T9 acceptance
   │                        ┘
   └── app ────▶ T10 codec+store slice ─▶ T11 ports.dart ─▶ T12 vocabulary ─▶ T13 glyph+mounts
                                                                   ├─▶ T14 desktop popover
```

Each task below states its **red test** and its **verify** command. A task is not done until
its verify command passes and the whole suite still does.

## T2 · `ports/scan.ts` — listeners

Red: `ports/scan.test.ts` against **fixtures captured from the real binary**, including the
`f`/`P` records the review found:

```
p669
u501
f10
PTCP
n*:61170
```

Cases: state persists across `f`/`P`/unknown records; one `p` → many `n`; `*:5173` →
`address:"*"`; `[::1]:9787` → `"::1"`; a name with no `:` or a non-numeric port is skipped;
spawn failure → `scanOk:false` + one-line reason; a non-zero exit that still parsed listeners
returns them (lsof warns routinely).

Green: `parseLsofListeners(stdout)` (pure) + `listListeners(exec)`.
Command: `lsof -nP -iTCP -sTCP:LISTEN -FpPnu`.
Verify: `npm test -- --test-name-pattern=scan`.

## T3 · `ports/proc.ts` — process table + cwds

Red: `ports/proc.test.ts`: argv containing spaces survives (a naive `split(/\s+/)` truncates
every command); `etime` shapes `mm:ss` / `hh:mm:ss` / `dd-hh:mm:ss` → `startedAt`;
unparsable `etime` **omits** it (never epoch 0 → "up 56y"); malformed line skipped, rest
kept; **`readCwds([])` issues no command** (an empty `-p` makes `lsof` dump the machine);
`realpath` cache resolves `/tmp/x` and `/private/tmp/x` to one key.

Green: `readProcs(exec)` → `Map<pid, {pid, ppid, startedAt?, command}>` via
`ps -axo pid=,ppid=,etime=,args=` (4 fields + rest-of-line); `readCwds(exec, pids)` via
`lsof -a -d cwd -Fpn -p <csv>`; `resolveReal(path)` memoised.
`rss` is **not** collected (D5). `Exec` imported as a type from `metrics/proc_table.ts`.
Verify: `npm test -- --test-name-pattern=proc`.

## T4 · `ports/ancestors.ts` — the derived pid set *(new, from the blocker)*

Red: a listener whose parent holds the worktree cwd must appear in the cwd request set;
a cycle (`a→b→a`) terminates; depth is bounded by `MAX_ANCESTOR_DEPTH`.

Green: `cwdPidSet(listenerPids, procs)` → listeners ∪ ancestors, so **one** `lsof -d cwd`
covers the ancestor fallback. Rev 1 requested cwds for listener pids only, which made the
documented `pnpm → node` fallback dead code.
Verify: `npm test -- --test-name-pattern=ancestor`.

## T5 · `ports/attribute.ts` — pure attribution

Red: `ports/attribute.test.ts` — the full table from the spec's Tests section: parent-owned
cwd; longest-prefix beats ancestor repo; `/a/b-2` ∌ `/a/b`; realpath aliasing;
`descendants(agentPid)` → `sessionId`; unowned stays unowned; `reach` ladder (wildcard →
`exposed`, exact tailnet IP → `tailnet`); `openUrl` for `127.0.0.1` / `*` / `::1` /
concrete, and **absent** without an HTTP verdict; `key` format; sort order.

Green: `attribute({listeners, procs, cwds, worktreePaths, sessionRoots, health, tailnetAddress})`
→ `PortDTO[]`. Pure. Uses `tree.ts` `childIndex` **once** for all listeners, not per listener.
Verify: `npm test -- --test-name-pattern=attribute`.

## T6 · `ports/health.ts` — the narrow probe

Red: `ports/health.test.ts` with an injected connector + clock: 200 → `ok`+status; 404 →
`http-error`; refusal → `refused`; hang → `timeout` at `PROBE_TIMEOUT_MS`; **an unowned port
is never probed**; a deny-listed port is never probed; malformed status line → `http-error`
(not a throw); cached `PROBE_TTL_MS` then re-probed; `PROBE_CONCURRENCY` respected.

Green: `PortHealthProbe` — `verdict(address, port)` / `refresh(ports)`; `refresh` never
throws (a failed probe is a verdict). Probes only ports with `worktreePath` (D3).
Constants named here: `PROBE_TIMEOUT_MS` 800, `PROBE_TTL_MS` 10_000, `PROBE_CONCURRENCY` 12,
`NO_HTTP_PROBE_PORTS`.
Verify: `npm test -- --test-name-pattern=health`.

## T7 · `ports/service.ts` — cadence + lifecycle

Red: `ports/service.test.ts` with a fake clock — **zero watchers ⇒ zero execs**; 0→1 runs
exactly one immediate scan; ticks every `SCAN_INTERVAL_MS`; a tick during an in-flight scan
is skipped (no overlap); 1→0 disarms; a scan completing after the last watcher leaves
publishes nothing; an identical snapshot does not re-broadcast (compare a projection that
excludes `scannedAt`); a throwing scan keeps the last good snapshot and sets `scanOk:false`.

Green: `PortsService` with everything injected — `{exec, probe, listWorktreePaths,
listSessionRoots, tailnetAddress, onSnapshot, now, setTimer}`. It imports **no** manager and
**no** session type: `listSessionRoots` is a supplied `() => Map<string, number>`, which is
the honest phrasing of rev 1's over-claim that the service "knows nothing about sessions".
Health `refresh` fires after publishing; its results land next tick.
Verify: `npm test -- --test-name-pattern=service`.

## T9 · `ports/acceptance.test.ts` — the real-machine proof

Red-by-construction: create a temp git repo + worktree, spawn a real `node -e` HTTP listener
with `cwd` set to it, run the **real** scanner (real `lsof`/`ps`), assert that port's

## Deviations log

Record every departure from this plan here as it happens, with the reason — the convention
SPEC-34-PLAN uses. Empty at the start.

| # | Task | Deviation | Why |
| --- | --- | --- | --- |
| 1 | T7/T8 | `tailnetAddress` is injected as a lazy memoised provider, not the value discovered at bind. | A value computed at construction spawns `tailscaleIP()` in every one of the 900+ server unit tests. **Reviewed and amended:** the lazy form put a *synchronous* subprocess (2 s timeout per candidate) on the scan path, so the address is now supplied from the already-discovered bind/cert value instead — the spec's original wording. |
| 2 | T8 | `WsClient.watchingPorts` + the two `CommandDeps` members were first added as **optional**. | Making them required broke ~9 pre-existing `FakeClient`/deps builders. **Reverted on review:** optional members meant a router built without them would ACK the watch, set the flag and then silently never scan — exactly the failure the metrics contract prevents. They are required, and the fakes were updated. |
| 3 | T11/T13 | `ports.watch` is sent fire-and-forget (`send`), not `request`. | `request` installs a 10 s ack-timeout timer; firing it on every row mount leaked pending timers and failed ~78 existing sidebar tests. The watch needs no ack — the server re-broadcasts the cached snapshot on watch-on — so this matches what `sub` already does. |
| 4 | T11/T13 | The watch is acquired **per row** (ref-counted to one `{on:true}`), not once per screen. | The ref-count is the mechanism designed to collapse N holders; per-row acquisition keeps the change inside the two row widgets instead of editing the home screen and the sidebar shell. Pinned by a test asserting the count returns to zero after dispose. |
| 5 | T14 | The popover is `OverlayPortal`, not `MenuAnchor`. | The spec named both `ComposerConfigOptions` (MenuAnchor) and `GithubBudgetButton` (OverlayPortal) as house patterns. `MenuAnchor` cannot cleanly express hover-dwell + pointer-bridge + click-to-pin + `esc`; the budget popover's shape can. |
| 6 | T2/T3 | `listListeners` / `readProcs` / `readCwds` return an explicit command-failure status rather than degrading to empty. | Found by review: `git.ts`'s `run()` never rejects — a missing or timed-out `lsof` resolves as `{code:127, stdout:""}`, so the first implementation reported a **successful empty scan** on any Linux host without `lsof`, wiping the ports list while claiming `scanOk:true`. |
| 7 | T5 | Health is read **after** ownership is resolved, not before. | Found by review: reading the cached verdict first meant a port that was worktree-owned (and therefore probed) and later became unowned kept its verdict *and* its `openUrl`, violating D3. |
| 8 | T8 | A non-boolean `on` in `ports.watch` is a true no-op. | Found by review: coercing any non-`true` value to `false` meant a malformed payload **disarmed** an active watch. The original test started from `false`, so it could not catch it. |
| 9 | T5 | `tailnet` requires the bind host to be inside **100.64.0.0/10**, not merely `100.*`. | Round-2 review: a bare `/^100\./` also matches 100.0.0.0/10 and 100.128.0.0/9, which are ordinary internet-routable space — it would have labelled a public bind `tailnet`, the reassuring reading of the alarming fact D2 exists to prevent. |
| 10 | T12 | A claimed duplicate-`Semantics` defect in `PortTokenPill` was **not** fixed. | Round-2 review (ocr) reported that `Tooltip`'s own semantics node doubles the explicit label, so a screen reader reads the sentence twice. Measured on this Flutter version: the nodes merge to a single utterance (`LABEL=[SENT]`), so the premise does not reproduce. A regression test now pins the invariant instead, because the failure mode is invisible without a screen reader. |

## Risks

| Risk | Mitigation |
| --- | --- |
| `lsof -F` output varies by version | pure parser + fixtures captured from the real binary; unknown records ignored, never fatal |
| attribution silently wrong | segment-wise prefix + realpath tests **and** T9's real-listener acceptance test |
| `lsof` slow under network mounts | 3 execs, 4 s cadence, watch-gated, timeout on every exec, no overlapping scans |
| probing something that hates HTTP | D3: only worktree-owned ports, minus a deny-list, loopback only |
| 16 pt-tall target reads badly in use | documented, with the uniform-20 pt fallback named |
| SPEC-37's 1 Hz `ps` and ours overlap | separate calls by design; ours is 4 s and only while watched |

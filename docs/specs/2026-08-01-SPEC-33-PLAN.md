### Corrections found while building (the plan was wrong about these)

1. **`info/exclude` lives in the git COMMON dir** — `--absolute-git-dir` points at
   `<main>/.git/worktrees/<n>`, where git never reads excludes, so `.makit/` showed
   up as untracked in the user's worktree. Fixed with
   `git rev-parse --path-format=absolute --git-common-dir` (T4).
2. **The echo must carry the user's ORIGINAL text**, not the path-suffixed prompt —
   otherwise the transcript shows people plumbing they never typed (T5).
3. **`StubAdapter` needed the same delivery path.** It has its own `send()`, so
   without it the keyless e2e loop would have "passed" while exercising nothing,
   and the dev/demo loop would silently drop images (T11 caught this).
4. **Gating on `session.worktreePath` was wrong.** The default repo-root session
   has `worktreePath == null` (verified by probing `ensureDefaultSessions`), yet the
   server materialises into the agent's *cwd* and delivers fine — so that gate would
   have disabled the paperclip for the commonest mobile case. The only real
   precondition is an upload endpoint (T10).
5. **`Clipboard.getData` has no default mock in widget tests** — an un-mocked call
   never completes, so the test *hangs* instead of failing. Tests install a
   `SystemChannels.platform` handler (T10).

### Post-review fixes (`ocr review`, 13 comments, 3 high)

6. **`store.put()` inside the `end` callback could crash the daemon.** Its
   synchronous fs work throws on ENOSPC/EACCES, and the route's outer try/catch
   only wraps the *synchronous* `handleUpload` call — an unguarded throw there was
   an uncaught exception. Now a local guard replies `500 upload_failed`, with a
   fault-injection regression test asserting nothing reaches
   `process.uncaughtException`.
7. **Clipboard/picker awaits had no disposal guards.** `_handlePaste`/`_pasteText`
   could mutate a disposed `TextEditingController`, and `showAttachMenu` used a
   `WidgetRef` across two async gaps. The composer now checks `mounted`; the menu
   resolves the notifier *before* awaiting (deliberately, so staging still lands
   when the widget goes away — the provider is non-autoDispose for that reason).
8. **The optimistic bubble hardcoded `mime: 'image/png'`.** Since that copy wins
   the seq dedup, a JPEG would have rendered as PNG forever. `wireFor` now carries
   the real mime, with a regression test.
9. Chips gained `ValueKey(localId)` (element reuse could flash one chip's spinner
   on another); clipboard reads use `BytesBuilder` instead of a boxed `List<int>`;
   an oversized paste now surfaces "too large to send" on the chip instead of
   being silently dropped (matching the picker path); chips stay visible while the
   composer is disabled so in-flight uploads cannot be stranded; `let turn` is
   typed `PreparedTurn` in all three adapters.

**Knowingly not changed:** ⌘V is claimed unconditionally, so the field's native
paste (undo stack, IME) is replaced by a manual one. Handing the intent back is
not possible — `EditableText` registers `PasteTextIntent` in an `Actions` map
*below* the `TextField`, so `Actions.invoke` from any context we hold throws
(verified). Reaching `EditableTextState` would mean walking the element tree,
which is worse. Documented at the call site.

Decisions baked in (2026-08-01): clipboard paste via **`super_clipboard` 0.9.1**,
exact-pinned, all platforms including Android (spec §4.3); delivery to the agent
is the **file hand-off** in v1, with a visible note on the sent bubble; inline
image content blocks are a **later phase** (spec §3.4b).

## T1 · `server/src/media/route.ts` — `POST /media`

- `handle()` currently 405s anything but GET/HEAD; add a `POST` branch **after**
  `authorized()` (auth before body reads — never buffer for an unauthenticated
  caller).
- Validate in order: `Content-Type` ∈ `MEDIA_MIME_ALLOWLIST` → `415`; missing or
  unparsable `Content-Length` → `411`; `> store.maxBlobBytes` → `413`.
- Accumulate chunks with a running byte count; exceed the cap or the declared
  length → destroy the request, `413`. Then `store.put(buf, mime)`.
- `201 {mediaId, mime, sizeBytes}`; `Cache-Control: no-store` on the response.
- Log metadata only (`mime`, `sizeBytes`), never a name.

**Tests** (`route.test.ts`): 401 unauth (and no body consumed), 415 bad mime, 411
no length, 413 over cap, 413 lying length (declares 10, sends 10 MB), 201 +
`GET` round-trip returns identical bytes, idempotent double-POST → same id.

## T3 · `send.message` validation

`server/src/ws/commands/session.ts:36`.

- `parseAttachments(raw, store)`: drop malformed entries; a well-formed id that
  `store.stat()` misses → return an error marker so the handler emits
  `BadRequest` (spec §3.3 — deliberately *not* dropped).
- `MAX_ATTACHMENTS = 8`; total-bytes cap. Over → `BadRequest`.
- Allow empty `text` **iff** attachments resolved; still require a string.
- Pending-session promotion (`promotePendingSession(session, text)`) names the
  branch from the text — with empty text it must not produce an empty branch
  name. Pass a fallback label (e.g. `"attachment"`); assert it.
- `Session.sendUserMessage(text, attachments?)` → `adapter.send({text, attachments})`.
- Log line gains `attachments=<n>`; no ids, no names.

**Tests** (`server/test/ws/`): unknown id → BadRequest; malformed entries dropped;
9 attachments → BadRequest; empty text + 1 attachment → accepted and forwarded;
empty text + no attachments → unchanged current behaviour; promotion label.

## T4 · `server/src/media/attach.ts` — file materialiser

New module (fs only), no adapter knowledge. **This is v1's delivery mechanism**,
so it carries the correctness weight — treat it accordingly.

- `materialise(store, attachments, worktreePath) → {absPath, name}[]`.
- Dir `<agent cwd>/.makit/attachments/` (the worktree when set, else the repo
  root); name `<mediaId.slice(0,7)>-<safe>`, where
  `safe` strips `[^A-Za-z0-9._-]`, collapses runs, rejects `..`/empty → falls back
  to `attachment.<ext from mime>`.
- Adds `.makit/` to `$GIT_DIR/info/exclude` once, idempotently (read → append if
  absent). Never touches a tracked `.gitignore`. Must work in a **worktree**,
  where `$GIT_DIR` is a file pointing into the main repo's `.git/worktrees/<n>`.
  **Measured correction (T4):** `--absolute-git-dir` is *also* wrong — git reads
  `info/exclude` from the **common** git dir, so an exclude written into the
  per-worktree dir is silently ignored and `.makit/` shows as untracked. Use
  `git rev-parse --path-format=absolute --git-common-dir`.
- `promptSuffix(files) → "\n\nAttached files:\n- …"` (empty string for none).
- No worktree → throw a typed error; the caller surfaces `session.error` (spec
  §5.5). Never silently drop the image.

**Tests:** sanitisation table (unicode, `../../etc/passwd`, empty, no extension),
collision-free naming, exclude-file idempotency **in a real linked worktree**,
suffix formatting, no-worktree error.

## T5 · Adapter plumbing — path form on both adapters

- `UserInput` (`adapters/adapter.ts:72`) gains `attachments?: MediaAttachment[]`.
- `acp.ts:245` and `codex.ts:188`: materialise via T4, append `promptSuffix` to
  the text, include descriptors in the `user.message` echo they already emit
  (`acp.ts:250`, `codex.ts:191`).
- Shared logic goes in T4/`session.ts`, not duplicated per adapter — the adapters
  should differ only in how they wrap the final text. **As built:** the shared
  seam is `prepareTurn(store, input, worktreePath)` in `media/attach.ts`, which
  returns `{promptText, echo}`. The echo carries the user's **original** text
  (not the suffixed prompt) — the transcript must show what they typed, not the
  path plumbing.
- Both adapters gained a `media` store option (defaulted to `sharedMediaStore()`)
  and codex now records `workspaceRoot` from `opts.cwd`.

**Tests** (`adapters/attachments.test.ts`): prompt text contains the path suffix
and the named file exists with the right bytes; echo keeps typed text + carries
descriptors; **no attachments → byte-identical payload to today** (regression
guard for the hot path); image-only turn still sends a non-empty prompt;
unwritable worktree → `session.error` and **no prompt sent**.

## T6 · `promptImage` reported (not yet used for sending)

> **Reverted by review.** The capability chain described below shipped and was then
> deleted: it drove exactly one caption, with the wrong polarity (it reported what
> the agent *could* accept, while the caption states what makit *did*), at the
> wrong granularity (per agent process, not per model — and the user can switch
> models mid-session), and on the wrong lifetime (a live session field applied to
> historical bubbles). The caption is unconditional today; phase (b) records
> `payload.deliveredAs` on the `user.message` event instead. See spec §3.5.

- **As built:** a separate `PromptCapabilities {image}` + `NO_PROMPT_CAPABILITIES`
  on the adapter interface, *not* a field on `SessionCapabilities` — that type is
  about the session lifecycle, and image support is not a lifecycle concern.
  `deriveAcpPromptCapabilities(init)` reads
  `agentCapabilities.promptCapabilities.image` (strict `true`); codex is a static
  `false`; `SubprocessAdapter`/`StubAdapter`/`DetachedAdapter` declare the default.
- Surfaced as `SessionDTO.promptImage` (`protocol.ts`) from
  `session.ts:toDTO()`.
- v1 consumer is **only** the hand-off note (spec §3.5). The send path does not
  branch on it — that is T12.

**Tests:** derivation present/absent/`false`/truthy-non-boolean; ACP adapter
reports `false` before `start()` and `true` after negotiating; codex reports
`false`.

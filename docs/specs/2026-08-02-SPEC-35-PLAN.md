## Deviations

1. **The queue ships on the sessions snapshot, not as a `session.queue` event.**
   `SessionDTO.queued: QueuedMessageDTO[]` replaced the planned event kind. An event
   kind goes through `record()` into the **durable** log, so after a server restart the
   replay would end on a stale non-empty snapshot and the app would show ghost chips for
   messages the (in-memory, decision 9) queue no longer holds. The DTO is derived from
   live state, is already broadcast on `metaChanged`, and is already reconnect-safe — and
   it avoids adding an `EventKind` with no historical meaning. Spec §Wire amended.
2. **The app no longer appends an optimistic user bubble while the agent is busy.**
   Not in the plan, but required for correctness and strictly a *fix*: the optimistic
   bubble guesses `cursor + 1` for its seq and `reduceEvent` drops anything with
   `seq <= cursor`. That guess is only right when the next server event is our own echo.
   Mid-turn the next seq belongs to the agent's stream, so the bubble was silently
   swallowing a real event (a delta, a tool update) — a latent bug that SPEC-35 would have
   made systematic. Guarded exactly like the existing replay/draft cases, with a
   regression test in `store_reducer_test.dart`.
3. **`attachmentCount`, not attachment descriptors, on the wire.** The chip only needs to
   say "and an image"; the bytes are already safe in the content-addressed store and the
   descriptors are rebuilt at flush. Smaller snapshot, nothing to keep in sync.
4. **A rejected steer may have already materialised attachments.** `turn/steer` needs the
   prompt text (which names the delivered files) *before* the request, so a refusal can
   leave a file in the worktree that the later flush writes again. Materialisation is
   content-addressed and idempotent, so this is a no-op in practice — documented at the
   call site rather than fixed with a second code path.
5. **An attachment-delivery failure inside `steer()` resolves `true`.** It reports a
   `session.error` and consumes the message: re-queueing a message whose file cannot be
   written would just fail again at flush, silently, on a timer.
6. **`queue.cancel` with an unknown id acks.** Made explicit (the plan said "no-op"): the
   message flushed between the tap and the frame, which is a race, not a client bug.

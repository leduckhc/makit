## T3 — queue in the session layer

`server/src/session.ts` (+ new `server/src/turn-queue.ts` only if `session.ts` would
otherwise grow a second responsibility; prefer inline until it hurts).

- RED (`session.test.ts`):
  1. busy + `steer()` false → message is queued, adapter `send` not called.
  2. `idle` → exactly one queued message is sent; the rest stay queued.
  3. three queued messages flush FIFO across three `idle` transitions.
  4. queue non-empty → a new `send.message` appends (never overtakes), even if the
     adapter reports idle.
  5. `cancel` empties the queue and interrupts.
  6. attachments: nothing is written into the worktree while a message is pending; the
     file appears at flush (assert with a temp `MediaStore` + `readdirSync`).
  7. session kill/exit drops pending items.
- GREEN: queue + flush-on-idle + priority rule from spec §Flush.

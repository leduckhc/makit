## Lanes

```text
Lane 1 (server: SDK + adapter + wire)   → verify: pnpm test + pnpm typecheck
Lane 2 (app: model layer)               → verify: flutter test --no-pub (models)
Lane 3 (app: composer renderer)         → after Lane 2 types merge
   └── all merge → Integration checkpoint
```

Lane 1 ∥ Lane 2 are independent (the wire shape is frozen in the spec — code
against it, not against each other). Lane 3 needs Lane 2's types compiled.

### Lane 1 — Server: SDK upgrade + `configOptions` plumbing
**Owns:** `server/package.json`, `server/src/adapters/acp.ts`,
`server/src/adapters/acp-map.ts`, `server/src/adapters/codex.ts`,
`server/src/protocol.ts` (+ server tests)

Serial within the lane:

1. **SDK 0.26 → 1.x.** Bump `@agentclientprotocol/sdk`; fix breaking changes
   until `pnpm typecheck` + existing `pnpm test` are green again. No behavior
   change in this step — it is the gate for everything below.
2. **Wire.** Add `SessionConfigOption` (incl. `groups` for grouped selects) +
   `configOptions?` to `session.meta` in `protocol.ts`; add the
   `session.action` kind `configOption {id, value}`.
3. **Capture + emit (red → green).** Tests first: `session/new` returning
   `configOptions` → emitted ordered on `session.meta.configOptions`, `modes`
   ignored when both present; `modes`-only agent → synthesised single
   `category:"mode"` option; grouped options parse into `groups`. Then
   implement in `acp.ts` (`emitMeta` grows the field; advertise
   `clientCapabilities.session.configOptions.boolean: {}`).
4. **Set + update (red → green).** Tests: `configOption` action →
   `session/set_config_option` (option `id` → wire `configId`), response's
   complete list re-emitted (never merged); `config_option_update` notification
   → re-emit; boolean value passes through. Keep `setSessionMode` only for
   agents that never sent `configOptions`.
5. **codex `app-server` projection (red → green).** Tests:
   `CodexAppServerAdapter` emits a `SessionConfigOption` catalog (`model` +
   `thought_level` reasoning effort) on `session.meta`; a `configOption` action
   maps onto `thread/start`/`turn/start` params; emitted shape identical to the
   ACP path's.

### Lane 2 — App: `SessionConfigOption` model
**Owns:** `app/lib/store/models.dart`, `app/test/store/` (model tests)

- Add `SessionConfigOption` / `ConfigOptionValue` / `ConfigOptionGroup` parsing
  from `session.meta.configOptions`; keep the legacy `model/thinking/modes`
  parsing untouched as fallback.
- Tests: parse select (flat + grouped), boolean, unknown category, ordering
  preserved; legacy-only meta still parses; both present → `configOptions`
  wins.

### Lane 3 — App: unified composer renderer
**Owns:** `app/lib/ui/composer/composer_selectors.dart`,
`app/lib/ui/composer/client_commands.dart`, composer widget tests

- One category-driven renderer replacing the three bespoke widgets: pill row in
  agent order — `model` → searchable sheet; `thought_level` →
  `ThinkingSignal` + level picker; `mode`/`model_config`/unknown → generic
  select sheet (grouped options render as labeled sections); `boolean` →
  toggle pill.
- Select → send `session.action configOption {id,value}`; **fully re-render**
  from the returned complete list (dependent options).
- Legacy fallback: when meta has no `configOptions`, render today's three
  selectors (native pi still uses them until SPEC-27).
- Widget tests: order respected; selection sends the action; dependent-option
  re-render; boolean toggle; grouped sections; legacy fallback still renders.

## Integration checkpoint (serial, after all lanes merge)

1. `cd server && pnpm typecheck && pnpm test` → green.
2. `cd app && flutter analyze --no-pub` (fatal-infos) + `flutter test --no-pub`
   → green; `app/tool/audit.sh` passes.
3. **Stub e2e:** `pnpm exec tsx test/e2e-server.ts --mode stub --project <path>` + a WSS client:
   a stub session emits `configOptions` in `session.meta`; `configOption`
   action round-trips.
4. Manual smoke (macOS, codex via `app-server`): composer shows the projected
   options (model + reasoning effort) as pills; changing them takes effect on
   the next turn.

- Lane 3 must not remove the legacy selectors' *code paths* (fallback), only

- Do **not** touch `catalog.ts`, `pi.ts`, `manager.ts` — that is SPEC-27.

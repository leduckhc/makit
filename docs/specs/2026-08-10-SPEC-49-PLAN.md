Commands ([`docs/DEVELOPMENT.md`](../DEVELOPMENT.md)): `flutter test --no-pub` and
`flutter analyze --fatal-infos --no-pub`, run in `app/`. **Never two `flutter test` processes at

## Order

One phase. T1 is the user's actual complaint and everything else hangs off the same widget, so
the order is simply "make it copyable, make that reachable without a mouse, then stop it
expiring under you".

```
T1 copy every notice, whole body ─▶ T2 keyboard + semantics ─▶ T3 hover/focus pause
   ─▶ T4 expand on contact ─▶ T5 input arbitration ─▶ T6 ⌘⇧C ─▶ T7 docs
```

Each task states its **red test**, its **verify** command, and the **mutation** that proves the
test bites. A task is not done until its verify passes, the whole suite still does, and the
mutation has been run by hand and seen to go red.

**Read first:** `app/lib/status/status_toast.dart` (especially `:223` the live region, `:275-302`
the `hasDetail`-gated copy button, `:59-112` the timer map),
`app/test/status/status_toast_test.dart:105-128` (the clipboard-mock precedent — reuse it, do not
invent a mechanism), `app/lib/status/activity_view.dart:257-293` (the expanded detail block to
reuse), `app/lib/shortcuts/{shortcut_action,keymap}.dart`,
`app/lib/desktop/chat/keymap_scope.dart:154-190`, `app/test/desktop/keymap_scope_test.dart`.

## T1 · Every notice copies, and the body is the target (D1, D6, D7)

Red: extend `test/status/status_toast_test.dart` —
1. an **`info` event with `detail == null`** shows a copy affordance and copying it writes exactly
   `event.toClipboardText()` (today there is no affordance at all for this event —
   `status_toast.dart:289` gates it on `e.hasDetail`, so this case fails first);
2. tapping the card **body** copies; the payload equals `toClipboardText()` byte-for-byte;
3. tapping the chevron calls `onOpen` and copies **nothing**;
4. a secondary-button click copies nothing;
5. after copying, the affordance reads `Copied` and reverts;
6. **the record is unchanged** — assert `center.snapshot.length` before and after (this is the D6
   guard and the one most easily written vacuously: count events, do not look for a widget).

Green: make the body an `InkWell`/`GestureDetector` whose `onTap` copies; delete the
`if (e.hasDetail)` gate and the `_ToastIconButton` copy button; move navigation to an explicit
chevron control. Keep `_copied` local state and the existing `_copyReset` timer.

Verify: `cd app && flutter test --no-pub test/status/status_toast_test.dart`
**Mutations:** (a) route the body tap to `onOpen` → case 2 red; (b) restore the `hasDetail` gate →
case 1 red; (c) copy `e.title` instead of `toClipboardText()` → case 2 red; (d) post a
`StatusEvent` on copy → case 6 red.

## T2 · Reachable without a pointer (D2)

Red: same file — the card is focusable (`Focus`/`FocusableActionDetector` reachable via
`tester.sendKeyEvent(LogicalKeyboardKey.tab)` or by requesting focus on its node); with focus,
`Enter` copies and `Space` copies; the card exposes a `Semantics` node whose label names the
severity and title and which offers a **named custom action** for copy (assert with
`tester.getSemantics` + `SemanticsAction.customAction`, not by finding a widget type); the
existing `liveRegion` (`status_toast.dart:223`) announces the `Copied` string.

Green: wrap the card in `FocusableActionDetector` with `Shortcuts`/`Actions` for
`Enter`/`Space`, and add `Semantics(label:…, customSemanticsActions: {…})`. Do not remove the
existing live region — extend its announced value.

Verify: `flutter test --no-pub test/status/status_toast_test.dart`
**Mutation:** drop the custom action (keep the tap) → the semantics assertion goes red while the
tap test still passes, which is exactly the gap this task exists to close.

## T3 · Hover or focus pauses the dwell; leaving restarts it in full (D4)

Red: same file, four cases —
1. **hover holds it:** `final g = await tester.createGesture(kind: PointerDeviceKind.mouse)`,
   `await g.addPointer(location: Offset.zero)`, `await g.moveTo(tester.getCenter(card))`,
   **`await tester.pump()`** (the enter must be processed on a frame before time advances — the
   repo's own hover tests do this, `test/message_navigator_rail_test.dart:161-167`), then
   `await tester.pump(dwell + 1s)` → the card is still present;
2. **leaving restarts the FULL dwell:** `await g.moveTo(Offset.zero)`, `await tester.pump()`, then
   `pump(dwell - 1ms)` → present; `pump(2ms)` → gone. A remainder-based implementation fails here;
3. **focus alone pauses it** with no pointer involved;
4. **no cap exists:** hold the hover for `dwell * 5` → still present.

Teardown: remove the pointer and let the layer unmount, so no `Timer` outlives the test
(`A Timer is still pending` is a documented failure mode in this repo —
`ui/session/navigator/jump_flash.dart:9-11`). Do **not** use an unbounded `pumpAndSettle` while a
dwell timer is live.

Green: `MouseRegion(onEnter/onExit)` + `Focus(onFocusChange:)` around the card; on pause cancel
that id's `Timer` in `_timers`, on resume reschedule with the **full** `toastDwell(severity)`. No
new constant, no new file — `toast_queue.dart` stays the pure crowding-rules file it says it is
(`toast_queue.dart:1-4`).

Verify: `flutter test --no-pub test/status/status_toast_test.dart`
**Mutations:** (a) do not cancel on enter → case 1 red; (b) resume with the remainder → case 2
red; (c) ignore `onFocusChange` → case 3 red.

## T4 · Contact or focus expands the detail in place (D5)

Red: same file — while hovered or focused, an event with a multi-line `detail` renders the
**whole** detail (assert the *last* line's text is present, which the one-line preview cannot
satisfy) and it is selectable (assert via the selection-capable widget's `SelectionArea`/
`SelectableText` **behaviour** — attempt a selection and read it back — rather than by widget
type, which is an implementation detail); leaving collapses it to one line.

Green: swap the collapsed preview for the block `ActivityView` already renders
(`activity_view.dart:257-293`) — extract it if needed so there is one detail block, not a third.

Verify: `flutter test --no-pub test/status/status_toast_test.dart`
**Mutation:** keep `maxLines: 1` when expanded → red.

## T5 · Input arbitration — one gesture, one meaning (D4, D7)

Red: same file — under `PointerDeviceKind.touch`, a tap on the body copies **and does not**
enter the paused/expanded state (a touch has no hover, so the two must not both fire); under
`PointerDeviceKind.mouse`, hover pauses **without** copying; a hover while keyboard focus is on
another card does not change that other card. Pump the **desktop shell** as well as the phone
shell for one case, because `_WorkspaceShellApp` (`main.dart:280-300`) runs the desktop tree on
iPad, so both input models can reach the same widget.

Green: gate the pause on `MouseRegion`/focus only (never on `Listener.onPointerDown`), and keep
copy on `onTap`.

Verify: `flutter test --no-pub test/status/`
**Mutation:** add `Listener(onPointerDown: pause)` → the touch case goes red.

## T6 · `⌘⇧C` copies the newest notice (D8, D9)

Red (a) `test/shortcuts/keymap_test.dart` — `copyNewestNotice` defaults to
`KeyChord(keyC, meta: true, shift: true)` under `cmdIsPrimary` and control+shift otherwise;
**no two actions share a chord** in the default map (assert over the whole map — the invariant,
not a brittle "nothing uses keyC"); every enum value has a binding; the action rebinds and
persists like any other.
Red (b) `test/desktop/keymap_scope_test.dart` — **the existing file**, not a new one — sending the
chord copies exactly the newest event's `toClipboardText()`; with an empty record it copies
nothing and throws nothing; it does **not** fire while `settingsOpenProvider` is `true`, and
neither does `toggleSidebar` (the pair proves the gate is intact rather than holed).

Green: one enum value in `shortcut_action.dart` (`ShortcutScope.global`), one line in
`keymap.dart` — `primary(LogicalKeyboardKey.keyC, shift: true)`, shaped like the shipped
`openPorts` — and one `case` in `_invoke` **below** the existing settings gate.

Verify: `flutter test --no-pub test/shortcuts/ && flutter test --no-pub test/desktop/`
**Mutations:** (a) bind `keyC` without `shift` → the collision invariant goes red; (b) move the
`case` above the settings gate → the gate test goes red; (c) copy `copyAllText()` → the payload
assertion goes red.

**Trap:** Riverpod asserts on changing the *number* of overrides between `pumpWidget` calls —
build the `ProviderScope` once in a helper and swap only its child.

## Risks

| Risk | Mitigation |
|---|---|
| Making the whole body a tap target could swallow a **text selection** drag inside the expanded detail. | T4 asserts selection behaviour, not widget type, so this fails loudly. If they fight, the detail block claims the drag and the *head* stays the copy target. |
| `FocusableActionDetector` on a card mounted above the `Navigator` could steal focus from the composer. | T2 asserts focus is *reachable*, not *taken*: the card must not autofocus. Add a case that typing into the composer still works with a notice up. |
| A hover pause with no cap can hold a notice indefinitely under a resting pointer. | Accepted deliberately (D4): hover is an act that ends when the pointer leaves, and the record holds the event regardless. |
| Semantics assertions are the least-practised test shape in this repo. | Use `tester.getSemantics`; if a mechanism resists, prefer a real behavioural assertion over deleting the requirement — the a11y contract is the point of T2. |

## Deviations log

| # | Task | Deviation | Why |
|---|------|-----------|-----|
| 1 | T2 | **Enter / Space already worked** — the tests for them passed *before* any production change. | `InkWell` is focusable and handles `ActivateIntent`, so once T1 moved `onTap` to `_copy` the keyboard path came free. So T2 shipped only the missing piece — the named `Copy` semantic action — instead of the planned `FocusableActionDetector` + `Shortcuts`/`Actions` wiring. Smaller diff, and the two keyboard tests are kept as regression guards rather than deleted. |
| 2 | T3 | Pause is driven by `MouseRegion` + `InkWell.onFocusChange`, **not** `FocusableActionDetector`. | Same reason as #1: the widget already had a focus callback. `onFocusChange` also turned out not to fire on a touch tap, which is exactly the arbitration T5 requires, so no `onShowFocusHighlight` gymnastics were needed. |
| 3 | T4 | The expanded detail is a local `SelectableText`, **not** an extraction of `ActivityView`'s block. | The spec's scope says "no change to `ActivityView`", and extracting the block would have edited a tested file for ~6 lines of shared styling. Accepted duplication over a wider diff (AGENTS.md §3). If a third copy ever appears, extract then. |
| 4 | T2 | `containsSemantics` → `isSemantics`. | `containsSemantics` is deprecated after v3.40.0 and `--fatal-infos` refused it. |
| 5 | T1 | Two **existing** tests were inverted rather than added to: `'no copy button when there is nothing machine-readable to copy'` (which asserted the D1 bug) and `'tapping the toast hands the event to onOpen'` (body tap → chevron, per D7). | Both encoded behaviour the spec deliberately changes. Each carries a comment naming the decision so the next reader sees intent, not drift. |
| 6 | — | No `git commit`. | The branch already carried ~57 files of uncommitted SPEC-48 work that is not mine to commit; the user was not asked for a commit. |

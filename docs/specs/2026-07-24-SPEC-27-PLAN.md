### Lane 0 — Server: drop native **pi**, pi over `pi-acp` (keep codex app-server)

`server/src/adapters/acp.ts` (registration only), affected server tests

- `catalog.ts`: transport stays `"acp" | "native"`; entries `pi` (acp, gated on
  **both** `pi-acp` and `pi` binaries resolving on PATH — makit wraps pi with
  the [pi-acp](https://github.com/svkozak/pi-acp) adapter, which spawns
  `pi --mode rpc`), `codex` (native, via `codex app-server`). Remove the
  **native pi** entry and the standalone `codex-native` label (fold into
  `codex`); `transportFor()` returns `acp` for pi, `native` for codex.
- Delete `pi.ts` (and its UI-interceptor wiring in `manager.ts` L82/L230);
  remove `spawnPiSession`'s pane path — all spawns headless (pi via ACP path,
  codex via `CodexAppServerAdapter`).
- Flip `catalog.test.ts` / `manager.test.ts` (pi-acp now expected; native pi
  absent; codex app-server retained). Keep `makit-mirror` extension code
  untouched but unreferenced (SPEC-05 retirement).
- Verify: `pnpm typecheck` + `pnpm test`; stub e2e still spawns and prompts for
  both pi (stub ACP) and codex (stub app-server).

### Lane 1 — Server: capability cache, fingerprint, probe, spawn picks
**Owns:** new `server/src/adapters/capability_cache.ts` (or similar),
`catalog.ts` (fingerprint fn), `acp.ts` (ACP probe helper), `codex.ts`
(app-server projection + probe), `server/src/ws/commands/session.ts`,
`server/src/protocol.ts`, server tests

TDD, in spec-plan order:

1. **Fingerprint + cache store.** Hash of resolved binary identity (path +
   file size + mtime) ⊕ catalog-affecting config (pi: `~/.pi/agent/models.json` +
   auth state). Store keyed `agentId → {fingerprint, configOptions?}` under the
   makit data dir. Tests: stable → no re-probe; touched `models.json`/binary →
   fingerprint changes.
2. **Probe (per transport).** ACP (pi) → `initialize` + `session/new` in an
   empty temp `cwd` → capture `configOptions` → **`session/delete`** (pi-acp
   supports it; cleans its `~/.pi/pi-acp/session-map.json` entry too) → kill.
   codex → project the app-server model/reasoning surface into
   `configOptions` (SPEC-26). Tests: catalog populated from a stub ACP adapter
   **and** a stub codex app-server; option-less harness → empty catalog; no
   ghost temp dirs; probe calls `session/delete` when the agent supports it.
3. **`agents.list` / `agents.refresh`.** Serve descriptors
   `{id, label, available, transport, fingerprint, configOptions?}` from cache;
   re-probe once on miss/change; `agents.refresh {agent}` forces. Wire in
   `protocol.ts`.
4. **`session.spawn` picks.** Optional `configOptions: [{id, value}]`
   validated against the cache (drop invalid), carried on the draft; on
   first-message launch applied per transport (ACP: `session/set_config_option`;
   codex: `thread/start`/`turn/start` params) after the real
   `session/new`, before the first prompt. Test picks hit the real session,
   not the probe.
